비원미래 AX Evidence Guide v2 — 경영진용 내레이션 대본
전체 1622자 · 차분히 읽으면 약 4분 16초 (영상 전체 4분 35초)

이 영상이 답하려는 것
  왜 AX를 실제 업무에서 계속 써야 하는가 · 프로그램을 만든 것과 실제로 쓴 것은
  무엇이 다른가 · 왜 기록이 계속 쌓여야 하는가 · 쌓인 데이터가 회사 성장에
  어떻게 쓰이는가

읽는 법
 · 열아홉 장면을 끊지 말고 한 번에 이어서 읽어 주세요. 파일 하나면 됩니다.
 · 장면 사이에는 아래 [쉼] 만큼 쉬어 주세요. 그동안 화면이 다음 장면으로
   넘어갑니다. 적힌 초는 짐작이 아니라 실제 촬영에서 화면이 걸린 시간입니다.
 · 대표님과 이사님께 설명드리는 자리입니다. 광고 낭독이 아니라 차분히.
 · 다 읽으신 파일은 video/audio/voiceover.evidence2.wav 로 넣어 주십시오.
   ⚠ 50초 short-demo · 2분 31초 v1 의 음성 파일과는 다른 파일입니다.

======================================================================

[S0 · 왜 이걸 만드는가]   어두운 글자 화면

폐기물과 물류처럼 현장이 중요한 산업에서도, 현장에서 나오는 데이터를 시스템으로 바꾸며 성장한 기업들이 있습니다.

   [쉼 약 0.5초]

[S1 · 유사 성장사례]   사례 카드 3장 — 금액 없이 구조만

폐기물 수거를 데이터 플랫폼으로 넓힌 리코, 물류 현장 데이터를 자체 SaaS로 키운 로커스코리아, 회수업무를 데이터화해 실증까지 간 써큘러랩스입니다.

   [쉼 약 1.0초]

[S2 · 공통점]   현장사업 → 데이터 → 시스템 → 실증 → 확장

업종은 달라도 공통점은 하나입니다.
현장사업을 버린 것이 아니라 현장의 경험과 데이터를 기술자산으로 바꿨습니다.
비원미래도 같습니다.

   [쉼 약 1.0초]

[S3 · 비원미래의 현장자산]   오늘 일정

비원미래에는 이미 실제 현장이 있습니다.
거래처가 있고, 매일 수거차량이 움직이고, 거래처마다 수거주기와 물량이 다르고, 자재와 배차, 수거이력, 정산이 계속 생깁니다.

   [쉼 약 2.0초]

[S4 · 데이터를 자산으로]   거래처

흩어져 있던 이 데이터를 AX 안에 쌓아야, 비원미래만 알던 현장 노하우가 회사의 자산이 됩니다.

   [쉼 약 2.0초]

[S5 · AX 코치]   AX 코치 — 준비도 · 네 갈래

그래서 AX 코치가 있습니다.
몇 번 눌렀는지 세는 것이 아니라, 실제 업무 기록을 보고 어떤 데이터가 충분히 쌓이고 있고 무엇이 아직 부족한지 확인합니다.

   [쉼 약 1.5초]

[S6 · 완료 단추가 없다]   오늘 이것만 해주세요

경고만 하지 않고 오늘 어떤 업무를 하면 그 데이터가 채워지는지 알려 줍니다.
완료 단추는 없습니다.
실제 기록이 생겨야 확인됩니다.

   [쉼 약 2.5초]

[S7 · 따로 하는 일이 아니다]   수거 입력 — 거래처 · 수거량 · 용기

현장 직원은 평소 하던 대로 합니다.
거래처를 고르고, 수거량과 차량을 넣고, 병원에 드린 용기가 있으면 함께 적고 저장합니다.

   [쉼 약 1.0초]

[S8 · 그 행동이 기록이 된다]   수거 입력 — 차량 · 저장

증거를 만들려고 보고서를 더 쓰는 것이 아닙니다.
원래 할 업무를 AX에서 하면 그 행동이 그대로 기록이 됩니다.

   [쉼 약 2.5초]

[S9 · 한 번 입력이 여러 업무로]   저장 결과 — 자동 연결 네 줄

이 한 번의 입력은 수거기록 하나로 끝나지 않습니다.
오늘 일정이 완료되고 수거이력이 생기고, 거래처 활동과 월간 물량이 바뀝니다.
자재 공급이력이 남고 사무실 재고가 줄고, 처리장 인계와 월간 관리자료까지 이어집니다.

   [쉼 약 2.5초]

[S10 · 첫 번째 실제 변화]   AX 코치 — 확인 · 준비도 44% → 46%

현장은 한 번 입력했지만 회사는 같은 데이터를 여러 업무에서 다시 씁니다.
이것이 AX를 도입했을 때 생기는 첫 변화입니다.

   [쉼 약 2.5초]

[S11 · 앞으로 잴 것]   AX 도입 성과 — 아직 측정하지 않은 항목

하지만 시스템을 만들었다는 사실만으로는 충분하지 않습니다.
도입 전과 후에 무엇이 달라졌는지를 실제 숫자로 남겨야 합니다.

   [쉼 약 1.5초]

[S12 · 재야 할 지표]   앞으로 측정할 지표 (덮개)

배차를 만드는 시간, 수거 한 건을 기록하는 시간, 누락과 재확인, 긴급수거 대응, 차량당 방문처, 한 사람이 감당하는 업무량입니다.
크게 보이는 숫자가 아니라 기록으로 검증되는 숫자여야 합니다.

   [쉼 약 1.5초]

[S13 · 변화가 보이기 시작한다]   AX 로 확인된 변화 세 칸

기록이 쌓이면 성과 화면에서 변화가 보입니다.
한 건을 처리하는 데 얼마나 걸렸는지, 한 번 입력한 데이터가 몇 개 업무에 다시 쓰였는지, 현장 기록이 당일 제대로 들어왔는지입니다.

   [쉼 약 1.0초]

[S14 · 억지로 만들지 않는다]   미측정 항목

아직 못 잰 것은 숫자를 만들지 않고 미측정으로 둡니다.
데이터가 쌓이면 배차와 수거패턴, 자재, 정산까지 깊게 볼 수 있습니다.

   [쉼 약 3.5초]

[S15 · 먼저 우리를 위해]   활용 계획 — 단계별 로드맵

이 데이터의 첫 번째 목적은 비원미래가 더 효율적으로 일하기 위한 것입니다.
나아가 기술을 개발했고, 직원이 실제 현장에서 썼고, 그 결과 업무가 어떻게 달라졌는지를 데이터로 설명할 수 있게 됩니다.

   [쉼 약 1.0초]

[S16 · 외부에 설명하는 근거]   플랫폼(SaaS) 전환 — 계획 수립됨 · 착수 전

정책자금과 R&D, 투자, 사업확장에서도 우리가 시스템을 만들었습니다가 아니라, 실제 현장에서 이것을 썼고 이런 변화가 확인됐습니다라고 설명할 근거가 됩니다.

   [쉼 약 1.0초]

[S17 · 확장의 기반]   성장 사다리 (덮개)

장기적으로는 비원미래 안에서 검증한 운영방식을 고객 포털과 다른 수거업체, 의료폐기물 운영 플랫폼으로 넓힐 수 있는 기반이 됩니다.

   [쉼 약 1.5초]

[OUTRO · 닫는 말]   어두운 글자 화면

비원미래 AX의 목표는 프로그램 하나를 만드는 것이 아닙니다.
현장의 경험을 데이터로, 그 데이터를 기술자산으로, 그 자산을 다음 성장으로 잇는 것입니다.
그래서 지금부터 가장 중요한 것은 AX를 실제 업무에서 계속 쓰고, 그 변화를 꾸준히 기록하는 것입니다.

화면에는 나오지만 읽지 않는 것
  · 사례 카드 아래 — 「제공된 리서치 자료 기준 · 성장 구조만 인용했습니다」
  · 앞으로 측정할 지표 — 「* 시스템에 아직 세는 칸이 없습니다 — 먼저 만들어야 합니다」
  · 성장 사다리 — 「정책자금 · R&D · 투자 · 사업 확장」

  ⚠ 「자금이 나온다」 「선정된다」 「기관이 인정한다」 「확률이 올라간다」 는
    대본에도 화면에도 넣지 않았습니다. 쓸 수 있는 데까지가
    「회사의 기술성과 실행력을 외부에 설명하는 근거로 활용할 수 있다」입니다.
  ⚠ 세 회사의 투자·보증 금액은 넣지 않았습니다 — 확인하지 못한 남의 회사
    숫자를 화면에 올리지 않습니다. 이름과 성장 구조만 인용합니다.

녹음하신 뒤
  1. video/audio/voiceover.evidence2.wav 로 넣습니다
  2. npm run video:evidence2:say   — 파일 길이를 재고 장면 시각의 출발점을 찍어 줍니다
  3. 들어 보고 고쳐서 video/config.evidence2.json 의 voiceover.marks 에 적습니다
  4. npm run video:evidence2      — 음성 붙은 MP4

  ⚠ 다시 녹음하시면 marks 숫자만 고치면 됩니다.
  ⚠ 앞선 두 편은 그대로 있습니다 — npm run video · npm run video:evidence
