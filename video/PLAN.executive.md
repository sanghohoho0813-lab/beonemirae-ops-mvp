## 1. 전체 구성과 시간

| INTRO | 여는 말 | 어두운 글자 화면 | 13.2s | 13s | 0:13 |
| PART 1 | 지금 무엇이 비었나 | AX 코치 — 준비도 · 네 갈래 | 18.4s | 19s | 0:33 |
| PART 2 | 업무로 연결 | AX 코치 — 오늘 이것만 해주세요 | 14.2s | 15s | 0:50 |
| PART 3 | 현장 입력 | 수거 입력 | 19.7s | 25s | 1:17 |
| PART 4 | 한 번 입력이 여러 업무로 | 저장 결과 | 20.6s | 23s | 1:42 |

| OUTRO | 닫는 말 | 어두운 글자 화면 | 8.1s | 9s | 2:32 |

장면 사이 전환 7번(약 9초)을 빼면 **약 2분 25초**입니다.
말만 128초(795자), 나머지가 화면이 움직이는 시간입니다.

**대표님 요청 범위와 다른 곳 두 군데 — 미리 말씀드립니다.**

- **INTRO 13초** (요청 8~12초). 주신 세 문장 중 앞 두 문장만 읽어도 13초입니다.
  급하게 읽으면 여는 말이 광고처럼 들립니다. 세 번째 「보조」 문장은 **글자로만
  띄우고 읽지 않습니다** — 같은 뜻을 PART 6 마지막에서 말로 합니다.
  (글로 한 번, 말로 한 번.)
- **PART 6 21초** (요청 15~20초). 투자·정책자금 이야기를 여기서 한 번은
  말로 해야 해서 1초 넘습니다.

3분을 채우려고 늘린 곳은 없습니다.

## 2. 화면에서 짚을 정확한 자리

강조는 **제품에 실제로 붙어 있는 표식(anchor)** 으로 잡습니다. 새로 만든
자리가 아니라 지금 화면에 있는 그 요소입니다.

### INTRO — 어두운 글자 화면 (앱 화면 아님)
영상 레이어가 그리는 전체 화면 카드입니다. 글자가 조용히 떠오르고, 끝나면
**250ms 만에 실제 AX 코치 화면으로 녹아듭니다.** 애니메이션은 이것뿐입니다.

```
AX를 도입하는 목적은
프로그램 하나를 만드는 것이 아닙니다.

실제 업무의 변화를 데이터로 남기고,
그 변화가 회사의 성장 증거가 되게 만드는 것입니다.

  (아래 작게)
  쌓인 기록은 운영 개선뿐 아니라 향후 투자·정책자금·R&D·사업 확장
  과정에서 회사를 설명하는 근거가 됩니다.
```

### PART 1 — `/ax-coach`
| 초 | 짚는 자리 | 화면에 보이는 것 |
|---|---|---|
| 0~4 | `[data-coach-total]` | 실증 자료 준비도 44% · 「성과가 44% 좋아졌다는 뜻이 아닙니다」 |
| 4~6 | `[data-coach-area="work"]` | 업무 활용 30% |
| 6~8 | `[data-coach-area="sales"]` | 매출 증거 0% |
| 8~10 | `[data-coach-area="capacity"]` | 운영 확장 69% |
| 10~12 | `[data-coach-area="customer"]` | 병원 직접사용 75% |
| 12~19 | 업무 활용 칸을 **눌러 펼침** → `[data-coach-items="work"]` | 무엇을 몇 건 세는지, 어디서 온 숫자인지 |

마지막에 다시 접습니다.

### PART 2 — `/ax-coach` (아래로)
| 초 | 짚는 자리 | 화면에 보이는 것 |
|---|---|---|
| 0~3 | `[data-coach-today]` | 오늘 이것만 해주세요 |
| 3~7 | 미션 세 장 전체 | 입금 대사 · 수거 입력 · 입력 빠진 방문 |
| 7~11 | 「했다」 단추 안내문 (`[data-coach-today] p.t-caption`) | 「「했다」 단추는 없습니다…」 |
| 11~15 | `[data-coach-go="collect-today"]` | 커서가 「수거 입력으로」를 누릅니다 |

### PART 3 — `/collect`
| 초 | 짚는 자리 | 동작 |
|---|---|---|
| 0~5 | `[data-guide="guide-client"]` | 거래처 고르기 |
| 5~8 | 폐기물 구분 · 주소 칸 | 거래처를 고르면 **저절로 채워지는 것** |
| 8~14 | `[data-guide="guide-amount"]` | 다녀온 날 · 시간 · 실제 수거량 70 입력 |
| 14~18 | `[data-tour="collect-supply"]` | 주고 온 자재 (→ 5번 「확인이 필요한 것」) |
| 18~21 | 8번 차량·기사 | 배차 차량 고르기 |
| 21~25 | `[data-guide="guide-save"]` | 커서가 「수거 완료 저장」을 누릅니다 |

### PART 4 — 저장 결과 `[data-tour="collect-done"]`
「한 번 입력으로 자동 연결됨」 네 줄을 **차례로** 짚습니다.

| 초 | 줄 |
|---|---|
| 0~2 | 카드 전체 — 「수거 완료가 반영되었습니다」 |
| 2~6 | 오늘 일정 완료 처리 · 수거이력 생성 |
| 6~10 | 거래처 최근 활동 · 월간 수거량 반영 |
| 10~14 | 대시보드·통계 수거량 반영 |
| 14~18 | 처리장 인계 상태 · 수거대장/월간 명세 초안 반영 |
| 18~23 | 카드 전체로 되돌아옴 |

⚠ 이 네 줄에는 개별 표식이 없습니다. 위치로 집습니다
(`[data-tour="collect-done"] .bg-navy-50 > p:nth-of-type(n)`).
제품을 고치지 않는 대신 화면 구조에 기대는 방식이라, 만들 때 네 줄이 제대로
잡히는지 눈으로 확인하고 보고드리겠습니다. 흔들리면 그때 표식 한 줄을
제품에 더할지 여쭙겠습니다.

### PART 5 — `/ax-coach` (왼쪽 목차의 「AX 코치」를 눌러 돌아감)
| 초 | 짚는 자리 | 화면에 보이는 것 |
|---|---|---|
| 0~5 | `[data-coach-done]` | 오늘 확인된 것 |
| 5~10 | 그 안의 확인 문구 | 「실제 업무기록을 확인했어요 — … 다녀온 날 안에 입력했습니다」 |
| 10~16 | `[data-coach-report-pct]` | 실증 자료 준비도 ○% → ○% |

**목차가 보이는 것이 여기서 값을 합니다** — 화면을 옮기는 것이 순간이동이
아니라 사람이 메뉴를 누르는 것으로 보입니다.

### PART 6 — `/performance` (왼쪽 목차의 「AX 도입 성과」)
| 초 | 짚는 자리 | 화면에 보이는 것 |
|---|---|---|
| 0~4 | 첫 변화 카드 | 수거 1건 입력 시간 0.7분 |
| 4~8 | 둘째 | 입력 1건이 자동 반영한 업무 5건 |
| 8~12 | 셋째 | 당일 입력 완료율 100% |
| 12~17 | `[data-perf-unmeasured]` | 아직 측정하지 않은 항목 8개 |
| 17~21 | 오른쪽 아래 | 「예시 데이터 · 기능 시연용」 |

⚠ **「기업 성장 현황」(2025년 매출 5.8억원 …)은 일부러 짚지 않습니다.**
그 칸은 회사 실적이지 AX 도입 효과가 아니고, 화면에도 그렇게 적혀 있습니다.
경영진용 영상에서 그 숫자를 강조하면 **AX 성과처럼 읽힐 위험**이 있습니다.
카드가 화면에 지나가는 것은 그대로 두되 강조하지 않습니다.

### OUTRO — 어두운 글자 화면
```
업무를 바꾸고,
그 변화를 데이터로 남기고,
그 데이터가 다시 회사의 다음 성장 근거가 됩니다.

            비원미래 AX · AX Coach
```

## 4. 짧은 Demo 에서 그대로 쓰는 것

바꾸지 않고 그대로 씁니다 —

- 촬영용 기록 `video/fixture.mjs` (지난 방문 12건 · 현장 입력 1건 · 포털 요청
  3건 · 오늘 예정 1건 · 미수 5건)
- 흉내 서버와 **바깥 요청 차단 그물** (실제 Supabase 요청 0건)
- 무대 CSS — 목차 188px(9.8%) · 기준 글자 19.5px · 본문 여백
- 커서 · 강조(테두리 0.58 · 빛 0.11 · 덮개 9%) · 자막 32px
- 「예시 데이터 · 기능 시연용」 표시
- 1920×1080 · 30fps · 녹화본 시간 늘어남 보정(`setpts`)
- 직접 녹음 음성 붙이는 길 (`voiceover.marks`) 과 어긋남 검사
- `mux.mjs` · `say.mjs` · `tts/` · `flicker.mjs`

**한 벌을 두 모드가 나눠 씁니다.**

```
video/
  record.mjs              ← 무대·커서·자막·흉내서버 (공통)
  flows/short-demo.mjs    ← 지금 그 다섯 단계 (제품 투어를 그대로 녹화)
  flows/executive.mjs     ← 이번 여덟 장면
  config.beonemirae.json  ← short-demo   (지금 것 그대로)
  config.executive.json   ← executive    (새로)
```

`npm run video` 는 지금과 똑같이 짧은 Demo 를 만듭니다.
`npm run video:exec` 가 이번 영상을 만듭니다.

⚠ `record.mjs` 를 나누는 동안 짧은 Demo 가 바뀌지 않았는지, **나누기 전후의
장면 시각과 증거 기록을 맞대어** 확인하고 보고드리겠습니다.

## 5. 새로 필요한 촬영 동작

| | 무엇 | 왜 |
|---|---|---|
| ① | **어두운 글자 화면** (여는 말 · 닫는 말) | 앱 화면이 아닙니다. 영상 레이어가 전체 화면 카드를 그리고, 250ms 로 실제 화면에 녹아듭니다. 애니메이션은 이것뿐입니다. |
| ② | **투어 없이 도는 흐름** | 제품의 심사 시연 투어는 다섯 단계뿐이라 스무 곳 넘게 짚지 못합니다. Executive 는 투어를 켜지 않고 화면을 직접 돌되, **강조는 지금과 똑같은 모양**을 영상 레이어가 그립니다. 화면은 100% 실제 제품입니다. |
| ③ | **한 화면 안에서 강조 옮기기** | 준비도 → 네 갈래 → 오늘 할 일처럼 같은 화면에서 여러 곳을 차례로 짚습니다. 짧은 Demo 에는 없던 동작입니다. |
| ④ | **네 갈래 카드 펼치기** | 「업무 활용」을 눌러 무엇을 세는지 보여 줍니다. 제품에 원래 있는 동작입니다. |
| ⑤ | **왼쪽 목차로 화면 옮기기** | PART 5·6 에서 커서가 목차의 「AX 코치」·「AX 도입 성과」를 누릅니다. 순간이동이 아니라 사람이 누르는 것으로 보입니다. |
| ⑥ | **목록 줄을 차례로 짚기** | PART 4 의 네 줄. 위치로 집습니다(위 2번 ⚠ 참고). |
| ⑦ | **입력 과정을 더 자세히** | 짧은 Demo 는 거래처·차량·수거량만 채웠습니다. 여기서는 날짜·시간·자재까지 보여 줍니다. |

## 6. 확인이 필요한 것 — 만들기 전에 답을 드리겠습니다

1. **「재고 차감」 줄을 보여 줄까요.**
   대표님 PART 4 목록에 **재고**가 있는데, 지금 저장 결과의 셋째 줄은
   자재를 **하나라도 주고 왔을 때만** 「자재 공급 이력 기록 · 사무실 재고
   차감」이 되고, 아니면 「대시보드·통계 수거량 반영」입니다.
   자재를 주려면 **사무실 재고가 있어야** 저장이 막히지 않습니다. 지금
   촬영용 기록에는 사무실 재고가 없습니다.
   → 촬영용 기록(`video/fixture.mjs`)에 **사무실 재고 몇 개**를 더하면
   됩니다. 금액은 만들지 않습니다. 넣을까요, 지금 네 줄 그대로 갈까요.
   (안 넣으면 내레이션에서 「재고」를 빼고 「통계」로 갑니다 — 지금 대본이
   그렇게 되어 있습니다.)

2. **PART 4 네 줄 집는 방식.** 표식이 없어 위치로 집습니다. 만들면서 확인해
   보고, 흔들리면 제품에 표식 한 줄을 더할지 그때 여쭙겠습니다.

3. **음성 파일 이름.** 짧은 Demo 와 섞이면 안 되므로
   `video/audio/voiceover.executive.wav` 로 따로 받습니다.
