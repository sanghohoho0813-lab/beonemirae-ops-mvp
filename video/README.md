| **짧은 Demo** | 심사위원용. 제품의 심사 시연 투어를 그대로 녹화 | **50초** | `npm run video` |
| **Evidence Guide v1** | 경영진용. 왜 실제 업무에서 계속 써야 하는가 | **2분 31초** | `npm run video:evidence` |
| **Evidence Guide v2** | 경영진용. 유사 성장사례부터 시작하는 전체 이야기 | **4분 35초** | `npm run video:evidence2` |

둘은 **촬영 엔진 한 벌을 나눠 씁니다.** 무대·커서·강조·자막·흉내 서버·
녹화본 시간 보정·직접 녹음 음성 붙이기까지 전부 같고, **무엇을 어떤 순서로
누르고 짚을지만** 다릅니다.

```
video/
  record.mjs                    ← 엔진 (무대·커서·강조·자막·흉내 서버)
  flows/short-demo.mjs          ← 50초  제품 투어를 그대로 녹화
  flows/evidence-guide.mjs      ← 2분30초 투어 없이 화면을 직접 돕니다
  config.beonemirae.json        ← 짧은 Demo
  config.evidence.json          ← Evidence Guide
```

`npm run video:evidence` 가 생겨도 `npm run video` 는 **한 줄도 달라지지
않습니다.** 나눈 뒤 장면 시각과 증거 기록을 맞대어 확인했습니다.

## 경영진용 v2 — 유사 성장사례부터 (0120)

v1 은 AX Coach 기능 설명부터 시작해서 「그래서 우리가 왜 이걸 해야 하는가」가
뒤늦게 나왔습니다. v2 는 순서를 바꿉니다 —

> 유사 성장사례 → 비원미래의 현장자산 → 왜 AX를 만들었는가 → 실제 사용
> → 운영 변화 → 앞으로 잴 지표 → 내부 성장 → 외부 확장

**열아홉 장면 · 1,622자 · 4분 35초.**

**지어낸 화면을 만들지 않습니다.**

- **앞으로 잴 지표** — 제품이 이미 들고 있는 「아직 측정하지 않은 항목」(8개)을
  **실제로 펼쳐** 보여 주고, 그 위에 대표님이 주신 여섯 지표를 얹습니다.
  시스템에 세는 칸이 아직 없는 둘(배차계획 작성시간 · 긴급수거 대응시간)은
  별표로 갈라 둡니다. 숫자는 한 칸도 적지 않습니다.
- **성장 로드맵** — `/roadmap` 에 **완료 · MVP 구현 · 예정 · 「계획 수립됨 ·
  착수 전」** 배지가 붙은 실제 화면이 있어 그대로 씁니다. 그 위에 지금 / 실증 중
  / 향후를 가른 사다리를 얹습니다.

**사례 카드에 금액을 적지 않습니다.** 확인하지 못한 남의 회사 숫자를 화면에
올리지 않습니다. 이름과 「현장사업 → 데이터 → 자체 시스템 → 실증 → 확장」이라는
구조만 인용하고, 카드 아래에 「제공된 리서치 자료 기준 · 성장 구조만
인용했습니다」를 답니다.

**돈 숫자가 잡히지 않게 화면을 골랐습니다.** 「비원미래에는 이미 현장이 있다」를
말하는 자리에서 대시보드를 쓰면 맨 위에 이번 달 매출이 같이 잡힙니다. 그래서
**오늘 일정**(거래처 · 차량 · 시간)과 **거래처 목록**을 씁니다. 성과 화면에서도
「기업 성장 현황」은 찍는 자리를 내려 화면 밖으로 보냅니다.

읽으실 대본은 `video/voiceover-script.evidence2.txt` 입니다.

## 경영진용 v1 — AX Evidence Guide (0119)

대상이 대표님과 이사님입니다. 기능 자랑이 아니라 **왜 실제 업무에서 계속
써야 하는가**를 이해하시게 하는 것이 목적입니다. 영상 전체를 한 줄이
관통합니다 —

> AX Evidence 는 심사를 위해 따로 만드는 자료가 아니라,
> 회사가 실제로 일하면서 남기는 변화의 기록이다.

| | 장면 | 화면 |
|---|---|---|
| INTRO | 왜 기록이 필요한가 | 어두운 글자 화면 |
| PART 1 | AX 코치가 지금 상태를 본다 | 준비도 · 네 갈래 · 「업무 활용」을 펼쳐 무엇을 세는지 |
| PART 2 | 부족한 것을 실제 업무로 | 오늘 할 일 · **「했다」 단추가 없다** · 미션 누름 |
| PART 3 | 따로 하는 일이 아니다 | 거래처 · 수거량 · **두고 온 용기** · 차량 · 저장 |
| PART 4 | 하나의 기록이 여러 업무로 | 저장 결과 네 줄을 한 줄씩 (재고 차감 포함) |
| PART 5 | 실제로 했는지 확인 | 오늘 확인된 것 · **같은 준비도 카드 46%** |
| PART 6 | 변화가 측정된다 | 변화 세 칸 · **아직 측정하지 않은 항목** |
| PART 7 | 왜 회사 성장에 중요한가 | 성과 화면 위에 마무리 문구 |
| OUTRO | 닫는 말 | 어두운 글자 화면 |

**투어를 켜지 않습니다.** 제품의 심사 시연 투어는 다섯 단계뿐이라 스무 곳
넘게 짚지 못합니다. 대신 강조는 **투어가 그리던 것과 같은 값**(덮개 9% ·
테두리 0.58 · 빛 0.11)을 영상 레이어가 그립니다. 화면은 여전히 100% 실제
제품입니다.

**일부러 짚지 않는 것 — 성과 화면의 「기업 성장 현황」**(2025년 매출 등).
그 칸은 회사 실적이지 AX 도입 효과가 아니고, 화면에도 그렇게 적혀 있습니다.
경영진 영상에서 강조하면 AX 성과처럼 읽힙니다. 화면에 지나가는 것은 그대로
두되 강조하지 않습니다.

**하지 않는 말** — 「이 데이터를 보여주면 자금이 나온다」 「기관이 Evidence
로 인정한다」. 쓸 수 있는 데까지가 「회사의 변화와 실행력을 설명하는 근거로
활용할 수 있다」입니다.

### 준비도 숫자를 한 줄로 잇습니다 (0119-b)

한때 **앞에서는 44%, 뒤에서는 33% → 46%** 였습니다. 셋 다 제품이 맞게 계산한
값이지만 기준이 달랐습니다 —

- `[data-coach-total-pct]` **44% / 46%** : 실증 시작일부터 **지금까지** 쌓인 것
- `[data-coach-report-pct]` **33%** : 그 셈을 **일주일 전** 날짜로 끊은 것

보는 사람에게는 기준이 셋이라 모순으로 읽혔습니다. 그래서 **같은 카드를 두 번**
보여 줍니다 — PART 1 에서 **44%**, 수거를 실제로 입력, PART 5 에서 **46%**.
숫자를 맞춘 것이 아니라 **같은 화면을 두 번 찍은 것**입니다. 네 갈래도 같이
올라갑니다 (업무 활용 30 → 35% · 운영 확장 69 → 72%).

### 성과 화면에서 찍는 자리 (0119-b)

「기업 성장 현황」(2025년 매출 등)이 화면 맨 위에 크게 놓이면 AX 성과로
읽힙니다. **제품은 그대로 두고 찍는 자리만 내립니다** — 촬영하는 창에서만 본문
아래 여백을 늘려 내려갈 자리를 만든 뒤, 「AX 로 확인된 변화」가 화면 맨 위에
오도록 굴립니다. PART 7 의 덮개 뒤 배경도 같은 자리입니다.

### PART 7 덮개

**62%** 입니다 (한때 74% 였는데 성과 화면이 배경으로 안 보일 만큼 어두웠습니다).
그 정도로는 흰 글씨가 흰 카드 위에서 잘 안 읽혀서, **글 뒤에만** 반투명 판을
따로 깝니다. 화면 전체를 어둡게 하는 것과 글만 띄우는 것은 다릅니다.

읽으실 대본은 `video/voiceover-script.evidence.txt` 입니다.

# 짧은 Demo (0118 · 1920×1080)

> 제품에 있는 **심사 시연 투어(demo · 다섯 단계)** 를 Playwright 가 사람 대신
> 눌러 가며 진행하고, 그 화면을 그대로 MP4 한 편으로 만듭니다.
>
> **투어를 복제하지 않습니다.** 단계 순서·문장·강조·덮개는 전부 제품의
> `TourOverlay` 가 그리는 그대로이고, 여기 있는 것은 「누르는 손」뿐입니다.
> 투어를 고치면 영상이 따라옵니다.

## 만드는 법

```bash
npm run build && npm run preview     # 다른 창에서 띄워 둡니다 (localhost:4173)
npm run video                        # 음성 → 녹화 → MP4
```

세 걸음을 따로 돌릴 수도 있습니다 — `npm run video:say` · `video:rec` · `video:mux`.
대사가 그대로면 음성은 다시 만들지 않습니다 (`--force` 로 강제).

결과물은 `video/out/` 에 생깁니다 (git 에는 올리지 않습니다).

| 파일 | 무엇 |
|---|---|
| `beonemirae-ax-60s.mp4` | **대표님이 보실 것** — 1920×1080 · 30fps · 한국어 음성 + 자막 |
| `silent-beonemirae-ax-60s.mp4` | 화면만 먼저 볼 때 (`npm run video:silent`) |
| `voice/*.wav`, `voice/timing.json` | 장면별 음성과 그 길이 · 자막 조각 |
| `demo.webm` | 브라우저가 남긴 원본 |
| `timeline.json` | 장면별 시각 + **아무것도 저장하지 않았다는 기록** |

따로 돌리려면 `npm run video:rec` · `npm run video:mux`.

## 실제 서버는 건드리지 않습니다

검사들이 쓰는 흉내 서버(`test/browser/walk_lib.mjs`)를 그대로 씁니다.

- 저장 요청은 흉내 서버가 받아 **성공한 척**만 합니다. 실제 Supabase 로는
  한 건도 나가지 않습니다.
- 바깥으로 나가는 요청은 **그물로 막고 세어서** `timeline.json` 에 남깁니다
  (`escapedRequests`). 정상이면 0건입니다.
- ⑤단계가 확인하는 「오늘 수거 완료 기록」도 흉내 서버가 만든 것입니다.
  다만 **확인 판정은 제품 로직 그대로**입니다 — 결과를 지어내지 않습니다.

그래서 화면 오른쪽 아래에 **「예시 데이터 · 기능 시연용」** 이 항상 떠 있습니다.

## 촬영용 기록 (0112)

기록이 하나도 없으면 AX 코치가 네 영역 모두 0% 라, 「아직 아무도 안 쓴다」로
보입니다. 이 영상이 보여 줄 이야기는 그게 아닙니다.

> 이미 일부 기록이 있다 → 코치가 **비어 있는 곳**을 찾는다 → 오늘 할 일을 준다
> → 사람이 한다 → 코치가 그 기록을 확인한다

그래서 `video/fixture.mjs` 에 **일부러 적은 양**을 고정으로 둡니다 — 지난 완료
방문 12건, **그중 현장 입력은 1건뿐**, 병원이 포털로 올린 요청 3건, 오늘 예정
1건. 「배차·완료는 하는데 현장 입력이 아직 안 쌓였다」는 그림이고, 그래서 오늘
할 일이 「수거 입력」이 됩니다.

**매출은 한 건도 만들지 않았습니다.** 주문·청구·입금을 지어내면 금액이 생깁니다.
「매출 증거 0%」로 남는 것도 사실입니다. 날짜는 오늘에서 며칠 전으로만 세므로
같은 날 몇 번을 찍어도 같은 화면이 나옵니다.

## 영상에만 더한 것 — 셋뿐입니다

1. 「예시 데이터 · 기능 시연용」 구석 표시
2. 부드러운 커서 (누르는 자리를 눈으로 따라갈 수 있게)
3. 오른쪽 위 도구 줄 감추기 — 제품은 투어가 끝나면 되돌려 놓는데, 영상에서는
   마지막 4초에 갑자기 나타나 산만합니다. **녹화하는 창에서만** 가립니다.

4. 하단 가운데 자막 — 내레이션과 **같은 문장**입니다.

넷 다 `record.mjs` 가 브라우저에 끼워 넣습니다. **`src/` 는 한 줄도 바뀌지
않습니다.** 자막은 일부러 넣지 않았습니다 — 투어 설명 상자가 이미 같은
문장을 크게 보여 줍니다. 아래쪽 자막 자리는 **AI 음성**을 붙일 때 씁니다.

## 화면 구성 (0118) — 「실제 시스템 화면을 보고 있다」

| | 값 |
|---|---|
| 왼쪽 목차 | **188px · 화면의 9.8%** (제 폭 392px 을 `zoom:0.48` 로) |
| 본문 | 1732px · 좌우 44px · 위 30px · 아래 110px 여백 |
| 기준 글자 | **19.5px** (0117 의 21.4 에서 9% 축소) |
| 자막 | **32px** · 두 줄까지 · 최대 폭 1382px(72%) · 바닥에서 **42px** |
| 강조 밖 덮개 | **9%** (0117 은 16%) |
| 강조 테두리 · 빛 | **0.58 · 0.11** (0118 은 0.80 · 0.16) |

0118-b 에서 셋을 더 다듬었습니다.

- **자막을 22px 내렸습니다.** ③단계에서 거래처·수거량을 채우는 칸을 덜
  가리려는 것입니다. 오른쪽 아래 예시 표시와는 여전히 가로로 겹치지
  않습니다 (자막 x 269~1651 · 표시 x 1684~).
- **강조 테두리와 빛만 약 30% 낮췄습니다.** 덮개(9%)는 그대로입니다 —
  어디를 보라는 표시는 되되 「선택된 칸」처럼 보이지 않게.
- **마무리는 고정된 몇 초가 아닙니다.** 말이 끝난 자리에서 **1초** 더
  성과 화면을 보여 줍니다. 직접 녹음으로 바꿔도 같은 규칙이라, 녹음이
  길든 짧든 꼬리는 늘 1초입니다.

0116~0117 에서는 목차를 아예 감추고 본문이 화면을 꽉 채우게 했습니다.
그랬더니 **「실제 시스템」이 아니라 「확대한 웹페이지」**로 보였습니다.
이제 목차를 얇게 되살리고 본문을 9% 줄입니다 — 화면 끝에 딱 붙지 않게
사방에 여백도 둡니다. 목차는 「오늘 업무」만 펼친 기본 상태 그대로입니다.

강조는 **「나머지를 감추는 것」이 아니라 「여기를 한번 보세요」**입니다.
덮인 자리의 글씨와 카드가 계속 읽혀야 합니다.

## 1920×1080 으로 찍어 1920×1080 으로 냅니다 (0117)

예전에는 1600×900 으로 찍어 1280×720 으로 줄였습니다. 줄이면 **글자 획이
뭉개집니다.** 이제 브라우저 창부터 1080 으로 열고 그대로 냅니다 — 늘려 키운
것이 아니라 처음부터 1080 으로 그린 화면입니다.

다만 창만 키우면 **같은 내용이 넓게 퍼져** 글자와 강조가 상대적으로
작아집니다. 그래서 이 앱의 기준 글자 크기를 화면 비율만큼 같이 키웁니다 —
`17.8px × (1920/1600) = 21.4px` (`config` 의 `stage.rootFontPx`). 배치 비율은
900 높이에서 맞춰 둔 그대로이고, 픽셀만 진짜 1080 입니다. **제품은 그대로**
이고 녹화하는 창에서만 덮어씁니다.

자막·구석 표시·커서도 같은 비율로 키웠습니다 (`stage`, `subtitle`).

**③단계(수거 입력)만 따로 손봤습니다.** 투어가 「수거 완료 저장」을 화면
가운데로 끌어오는데, 그러면 정작 채워 넣는 칸(거래처·수거량)이 위로 밀려
보이지 않았습니다. 말로는 「거래처와 차량, 수거량을 입력합니다」라고 하면서
화면에는 그 칸이 없는 셈입니다. 그래서 채우는 동안에는 그 칸이 보이는 자리로
올렸다가, 누를 때 단추로 내려갑니다. 강조 테두리는 스크롤을 따라다닙니다.

## 음성과 자막 (0114)

**장면이 머무는 시간을 음성이 정합니다.** 고정된 초가 아닙니다.

1. `say.mjs` 가 대사 6개를 음성으로 만들고 **길이를 잽니다** → `voice/timing.json`
2. `record.mjs` 가 그 길이만큼 화면을 붙잡습니다. 말이 끝나면 0.4초 쉬고 넘어가되,
   **화면에서 할 일이 남아 있으면 그것까지 끝난 뒤에** 넘어갑니다 — 다음 장면의
   말이 화면보다 앞서 나가지 않게 하려는 것입니다.
3. `mux.mjs` 가 각 음성을 제 시작 시각에 놓고 하나로 섞습니다.

편집 프로그램이 필요 없는 이유가 이것입니다 — 찍을 때 이미 맞춰 두었습니다.

**자막을 끊는 기준** (`say.mjs`)
① 문장(마침표)으로 → ② 길면 쉼표에서 한 번 더 → ③ 그래도 길면 띄어쓰기에서
**두 줄까지만** → ④ 조각이 보이는 시간은 **글자 수에 비례**해 나눕니다.
문장을 줄이거나 바꾸지 않습니다 — 읽는 말과 적히는 말이 같아야 합니다.

## 촬영 무대 (0116) — 화면의 거의 전부가 실제 AX

촬영하는 창에서만 CSS 로 바꿉니다 (`src/` 는 그대로).

- **왼쪽 목차를 접습니다.** 처음부터 접어 둡니다 — 중간에 사라지면 그 자체가
  눈에 띄는 장면이 되고, 그걸 감추려 화면을 덮으면 더 정신없습니다.
- **본문이 화면 가로를 그대로 씁니다.** 오른쪽에 설명 상자 자리를 비워 두던
  것을 없앴습니다.
- **투어 설명 상자를 감춥니다.** 큰 설명 박스가 계속 떠 있으면 「AX 소개영상」이
  아니라 「튜토리얼 기능 녹화」로 보입니다. 설명은 **음성과 자막**이 맡고,
  왼쪽 아래에 「1/5 · AX 코치」 정도만 아주 작게 둡니다.
- **강조는 얇은 테두리와 은은한 빛까지만.** 예전에는 나머지 화면을 72%
  어둡게 덮어 실제 내용이 잘 안 읽혔습니다. 지금은 16% 입니다.

우선순위: **실제 AX 화면 > 강조 대상 > 커서 > 자막 > 그 밖**.

단계 진행은 제품의 그 투어 그대로입니다. 설명 상자를 감췄으므로 읽는 단계는
투어의 「다음」을 제품 쪽에 바로 알려 넘깁니다 — 보는 사람에게는 화면이 저절로
다음으로 넘어가는 것으로 보입니다. **커서는 화면에 실제로 보이는 AX 단추**
(「수거 입력으로」·「수거 완료 저장」)를 누를 때만 움직이고, 설명을 듣는 동안은
오른쪽 여백으로 물러나 옅어집니다.

## 전환

**전체 화면을 어둡게 덮었다 밝히는 방식은 없앴습니다.** 0115 에서 시험해
봤는데, 숫자로는 좋아져도 **눈에는 더 깜빡이고 정신없었습니다.** 지금은 다음
화면이 준비되면 그대로 넘어갑니다 — 강조가 옅어진 덕에 덮개가 걷혀도 계단이
생기지 않습니다.

확인은 `npm run video:flicker` — 프레임마다 평균 밝기를 재서 **튐**(번쩍였다
되돌아옴)과 **뚝**(한두 프레임 만에 큰 변화)만 골라 냅니다. 다만 **숫자보다
사람 눈이 먼저입니다** — 숫자가 좋아도 어색하면 그 방식은 버립니다.

## 속도 (0118)

전체가 **50.7초**입니다. 말이 44.2초, 나머지 6.5초가 화면이 넘어가는
시간입니다. 줄인 곳은 `config` 의 `hold` 에 전부 숫자로 있습니다 — 누르기
전후의 뜸, 화면이 바뀐 뒤의 여백, 커서 속도, 말이 끝난 뒤의 쉼.

**시작 화면은 약 0.9초**입니다. 영상이 시작되고 1초가 되기 전에 실제 AX
화면이 나옵니다. 인트로 영상이나 제목 애니메이션은 만들지 않았습니다.

일부러 남겨 둔 시간도 있습니다 — 저장 결과 화면은 **8.2초**(최소 2초 요구),
마지막 성과 화면은 말이 끝난 뒤 **1초** 더 (숫자를 읽을 시간).

⚠ 0117 의 367자 대본은 사람이 차분히 읽으면 60초를 넘겼습니다. 대표님이
**283자**로 줄여 주신 것을 최종 음성 대본으로 씁니다 — 읽으실 원문은
`video/voiceover-script.txt` 에 장면별 쉼까지 적어 두었습니다.

## 녹화본의 시간이 실제 시간과 다릅니다 (0118)

**Playwright 가 남기는 webm 은 실제로 흐른 시간과 길이가 다릅니다.** 화면이
멈춰 있으면 프레임을 덜 만들고, 그것을 되살리면서 길이가 1~3% 늘어납니다
(51초짜리에서 1.5초쯤). 그래서 앞부분을 자를 때

- 끝에서 되짚어도 (영상길이 − 닫을 때까지)
- 앞에서 세어도   (페이지 연 뒤 흐른 시간)

둘 다 어긋났고, 어긋난 채로 잘랐더니 **시작 화면이 통째로 사라졌습니다.**

지금은 녹화하면서 **실제로 흐른 시간**을 재 두고(`videoWallSec`), 합칠 때
`setpts` 로 영상 시간을 그 비율만큼 되돌린 뒤 자릅니다. 얼마나 되돌렸는지는
합칠 때 화면에 찍힙니다 — `영상 시간 보정 ×0.97` 처럼.

## 직접 녹음한 음성을 붙이려면 (0117)

`video/audio/voiceover.wav` (또는 `.mp3` · `.m4a`) **하나**를 넣으면 TTS 를
만들지 않고 그 파일을 씁니다. 대본 여섯 장면을 한 번에 이어서 읽고, 장면과
장면 사이만 쉬어 주시면 됩니다.

읽으실 대본은 **`video/voiceover-script.txt`** 에 있습니다 — 장면별 문장과
「여기서 몇 초 쉬세요」까지 적혀 있습니다. Voicebox 같은 곳에서 그대로
읽으시면 됩니다.

```bash
npm run video:say     # 파일 길이를 재고, 구간의 「출발점」을 찍어 줍니다
#  들어 보고 고쳐서 config 의 voiceover.marks 에 적습니다
npm run video         # 음성 붙은 MP4
```

`marks` 는 **그 녹음 안에서** 각 장면이 시작하는 시각입니다.

```json
"marks": {
  "s1": "0:00.50",
  "s2": ["0:10.82", "0:17.31"],   // 끝까지 적으면 자막이 정확히 맞습니다
  ...
  "end": "0:55.28"
}
```

**다시 녹음하시면 이 숫자만 고치면 영상이 다시 만들어집니다.** 음성을
분석해 자동으로 찾아 주는 것은 만들지 않았습니다 — 손으로 적는 편이
확실하고, 지금 필요한 것도 그게 아닙니다.

**장면 사이에 얼마나 쉬어야 하는가.** 화면이 다음 장면까지 가는 데 시간이
걸립니다(누르고, 화면이 바뀌고, 자리를 잡고). 녹화가 끝나면 그 시간을
찍어 줍니다 —

```
  녹음할 때 장면 사이에 필요한 최소 간격
    s2     앞에서 0.4초
    s3     앞에서 1.5초
    s4     앞에서 2.1초     ← 저장 → 결과 화면
    s5     앞에서 0.7초
    outro  앞에서 0.5초
```

이보다 짧게 쉬면 **말이 화면을 앞지릅니다.** 그런 장면은 녹화할 때
`⚠ 화면이 음성보다 늦은 장면` 으로 몇 초씩 늦었는지 알려 주고
`timeline.json` 의 `voiceLag` 에도 남습니다. 조용히 넘어가지 않습니다.

붙이는 자리는 간단합니다 — 파일 안의 `s1` 시각이 영상의 `s1` 자리에 오도록
**통째로 밀거나 당깁니다**(`mux.mjs`). 장면을 잘라 붙이지 않습니다.

## 음성 공급자를 바꾸려면

`video/tts/` 안에 파일 하나를 더 만들고 `video/tts/index.mjs` 의 `PROVIDERS` 에
한 줄 더한 뒤, `config` 의 `tts.provider` 이름을 바꾸면 끝입니다. 목소리 설정은
`tts.voices.<공급자>` 아래에 따로 두어 값이 섞이지 않습니다.

**지금 붙어 있는 것**

| 공급자 | 열쇠 | 쓰임 |
|---|---|---|
| (직접 녹음) | 없음 | **심사 최종본** — 위 「직접 녹음한 음성」 |
| `piper` | 없음 | 녹음 전에 화면 타이밍을 잡아 보는 용도 |
| `elevenlabs` | `ELEVENLABS_API_KEY` | 지금은 쓰지 않습니다 (구현은 그대로 둡니다) |

직접 녹음한 파일이 있으면 **TTS 는 아예 부르지 않습니다.** 파일을 치우면
다시 `tts.provider` 가 하던 대로 돌아갑니다.

```bash
export ELEVENLABS_API_KEY=...
npm run video:voices                 # 목소리 목록에서 고릅니다
npm run video:say -- --only s1,s2    # 앞 두 장면만
npm run video:sample                 # 15~20초 들어 보기
```

여섯 장면 모두 **같은 voice · model · settings** 를 씁니다. 앞뒤 문장을
`previous_text` · `next_text` 로 함께 보내 문장 사이 호흡을 잇습니다.

**`record.mjs`(녹화·자막)와 `mux.mjs`(합치기)는 손대지 않습니다.** 그 둘이 아는
것은 「장면마다 wav 가 하나 있고 몇 초짜리인지」뿐입니다.

열쇠가 필요한 공급자는 **환경변수로만** 받습니다 — 코드·깃·문서에 적지 않습니다.
