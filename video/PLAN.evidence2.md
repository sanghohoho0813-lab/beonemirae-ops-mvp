선이 거기까지입니다. 그보다 짧으면 사례와 로드맵이 스쳐 지나가고, 그보다 길면

## 4. INTRO 유사기업 사례 카드 구성

어두운 글자 화면 위에 카드 세 장을 **차례로** 띄웁니다 (각 4~5초).

```
┌──────────────────────────────────────────────┐
│ 리코                                          │
│ 사업장 폐기물 수거·관리                        │
│ → 데이터 · 플랫폼 사업으로 확장                 │
│ 2025년 585억원 규모 투자   [제공된 리서치 기준]  │
└──────────────────────────────────────────────┘
┌──────────────────────────────────────────────┐
│ 로커스코리아                                   │
│ 직접 물류센터 운영 → 현장 데이터 축적            │
│ → 자체 WMS·OMS SaaS → TMS·ERP·CRM·AI 확장      │
│ 2026년 퍼스트펭귄 30억원  [제공된 리서치 기준]   │
└──────────────────────────────────────────────┘
┌──────────────────────────────────────────────┐
│ 써큘러랩스                                     │
│ 현장 회수업무 → RFID·NFC 데이터화               │
│ → 실제 현장 실증 → 순환경제 플랫폼               │
│ 2026년 리틀펭귄 약 20억원  [제공된 리서치 기준]  │
└──────────────────────────────────────────────┘
```

그다음 한 줄로 공통 구조만 남깁니다.

```
현장사업  →  데이터  →  자체 시스템  →  실증  →  확장

           비원미래가 AX를 만드는 이유도 같습니다
```

**화면 아래에 늘 붙여 둘 한 줄** —

> 제공된 리서치 자료 기준 · AX 도입으로 받은 것이라는 뜻이 아닙니다

### ⚠ 이 부분은 대표님 확인이 필요합니다

세 회사의 **금액과 연도를 제가 확인하지 못했습니다.** 주신 리서치 자료에 적힌
그대로 화면에 올립니다. 다른 회사의 투자·보증 금액을 영상에 적는 일은, 숫자가
틀리면 그 영상을 보는 자리에서 바로 지적당합니다. 세 가지 중에 골라 주십시오.

1. 숫자를 그대로 쓴다 (출처 표시 유지) — 대표님이 원문을 확인하셨다면
2. **숫자를 빼고 흐름만 쓴다** — 「현장사업 → 데이터 → 자체 SaaS → 확장」
   (제 의견입니다. 이 영상에서 필요한 것은 금액이 아니라 *구조*입니다)
3. 출처 이름을 화면에 같이 적는다 — 어느 기사·자료인지 한 줄로

## 5. KPI 화면 구성 — 「앞으로 측정할 지표」

**지어낸 화면을 만들지 않습니다.** 제품이 이미 「아직 측정하지 않은 항목」을
들고 있습니다. `/performance` 에서 그 목록을 **실제로 펼쳐** 보여 줍니다
(`[data-perf-unmeasured-toggle]` — 지금 8개).

제품이 이미 세고 있는 것 (펼치면 이유까지 같이 나옵니다)

```
수거 1건 사무업무 시간      도입 전 기준값 미입력
같은 정보를 다시 적는 횟수   엑셀 확인 응답 0/N일
월간 문서·정산 정리 시간     도입 후 같은 범위 조사 없음
완료 취소 후 재입력 건수     …
하루 처리 건수 (회사 전체)   입력 커버리지 N%
포털을 직접 쓴 병원          포털 요청·주문 없음
처리시설 대기               기사님 마감에 대기시간 기록 없음
운행거리 (계기판)            기사님 마감에 계기판 기록 없음
```

그 위에 대표님이 주신 여섯 지표를 카드로 얹습니다.

```
           앞으로 측정할 지표 — 아직 값이 없습니다

  배차계획 작성시간 *        수거 1건 처리시간
  누락 · 재확인 건수         긴급수거 대응시간 *
  차량당 일평균 방문처        직원 1인당 처리 업무량

  * 시스템에 아직 세는 칸이 없습니다 — 먼저 만들어야 합니다
```

**별표 둘은 솔직하게 갈라 둡니다.** 「배차계획 작성시간」과 「긴급수거 대응시간」은
지금 시스템이 세지 않습니다. 나머지 넷은 위 목록과 이어집니다. 숫자는 한 칸도
적지 않습니다.

## 6. 성장 로드맵 화면 구성 — **제품 화면을 씁니다**

`/roadmap` 에 이미 있습니다. 지어낸 카드보다 이쪽이 훨씬 셉니다 — 화면마다
**상태 배지**가 붙어 있어 「완성된 것처럼」 보이지 않습니다.

| 제품의 단계 | 상태 배지 |
|---|---|
| 1단계 현재 MVP 안정화 | **완료** |
| 2단계 반복입력 자동화 | **MVP 구현 · 현재** |
| 3단계 서버 전환 및 권한 분리 | **완료** |
| 4단계 병원 고객 서비스 | **MVP 구현** |
| 5단계 정기 운영관리 · SaaS 확장 | **예정** |
| 플랫폼(SaaS) 전환 | **계획 수립됨 · 착수 전** |

마지막 카드에는 제품이 이렇게 적어 두었습니다 — 그대로 보여 줍니다.

> 현재 시스템은 ㈜비원미래 전용 단일 회사 구조입니다. 자사 실운영으로 업무
> 모델을 먼저 검증한 뒤, 5단계로 다른 수거·운반 회사도 쓰는 서비스로
> 전환합니다. … 기간·비용은 투입 구성이 정해진 뒤에 적습니다.

그 위에 주신 사다리를 **요약 오버레이 한 장**으로 겹칩니다.

```
현재   의료폐기물 수거·운반                     [지금]
 ↓
1단계  자체 AX 로 내부 운영 데이터화            [실증 중]
2단계  의료기관 고객포털                        [실증 중]
 ↓
3단계  배차·수거·자재·정산 데이터 고도화         [향후]
4단계  타 수거·운반업체 적용 · 업종 특화         [향후]
 ↓
장기   의료폐기물 운영 플랫폼                    [향후]

        현장사업 → 데이터 → 시스템 → 반복 실증 → 플랫폼 확장
```

## 7. 현재 구현 / 향후 확장 구분

영상에서 **말과 화면 양쪽에** 이 구분을 유지합니다.

| | 지금 되는 것 (영상에 실제 화면이 나옴) | 실증 중 | 향후 |
|---|---|---|---|
| 수거 입력 1회 → 일정·수거이력·거래처·자재·재고·인계·명세 초안 | ● | | |
| AX 코치 — 준비도 · 부족한 데이터 · 오늘 할 일 · 실제 기록 확인 | ● | | |
| AX 도입 성과 — 입력시간 · 자동반영 업무 · 당일 입력률 · 미측정 | ● | | |
| 병원 고객포털 (현황 · 요청 · 리포트) | | ● | |
| 배차·경로 추천 고도화 | | | ● |
| 배차계획 작성시간 · 긴급수거 대응시간 측정 | | | ● |
| 타 수거·운반업체 적용 (다회사 구조) | | | ● 계획 수립됨 · 착수 전 |
| 의료폐기물 운영 플랫폼 | | | ● |

**하지 않을 말** — 「자금이 나온다」 「선정된다」 「기관이 인정한다」
「확률이 올라간다」. 쓸 수 있는 데까지가 **「회사의 기술성과 실행력, 성장
가능성을 외부에 설명하는 근거로 활용할 수 있다」** 입니다.
