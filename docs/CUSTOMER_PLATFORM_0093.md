# 0093 — 안정화 · 품질 점검

> 대표님 지시: 「지금까지 최근 며칠동안 개발했던거 오류는 없는지 여러차례 테스트
> 해봐서 오류 아예 없애고 퀄리티 올리는 작업 한 번 들어가자」
>
> 새 기능을 넣는 회차가 아닙니다. **0086~0092 에서 만든 것이 실제로 맞게
> 도는지**를 여러 번 돌려 확인하고, 나온 결함을 없앤 회차입니다.

---

## 1. 가장 큰 발견 — 「실패 0」이 거짓말이었습니다

브라우저 회귀는 스위트가 찍은 `OK` / `FAIL` 줄을 세서 합계를 냅니다.
그런데 스위트가 **도중에 터지면** 그 뒤로는 아무 줄도 안 찍습니다.
줄만 세는 겉껍질은 그것을 「실패 0」으로 읽습니다.

0089 에서 수거 요청 창을 **적는 창 → 고르는 창**으로 바꾸면서
`#req-content` · `#req-date` · `[data-req-kg]` · `[data-req-sent]` 가
없어졌습니다. 그 칸을 찾던 스위트 셋이 그때부터 조용히 죽어 있었습니다.

| 스위트 | 죽어 있던 모습 | 지금 |
|---|---|---|
| `check_e2e88` | 창을 못 찾고 터짐 · **검사 0건** | 38건 · 실패 0 |
| `check_reqdup` | 창을 못 찾고 터짐 · **검사 0건** | 14건 · 실패 0 |
| `check_flow390` | 35건 찍고 6단계에서 터짐 | 64건 · 실패 0 |

되살린 검사 **81건**입니다. 그중에는 이런 것들이 있었습니다.

* 통신이 끊겨 **다시 눌렀을 때 같은 저장시도 표를 보내는가** — 이게 없으면
  서버의 중복 방어가 아무 일도 못 하고 요청이 두 건 들어갑니다(차가 두 번 갑니다).
* 성공한 뒤에는 **새 표**를 쓰는가 — 이게 없으면 진짜 두 번째 요청이 조용히 사라집니다.
* 병원이 올린 요청이 직원 요청함 → 일정 반영 → 병원 화면으로 **왕복**하는가.
* 다른 병원 자료가 섞이지 않는가.

3개월 가까이 이 검사들이 **한 번도 안 돌고 있었습니다.**

### 고친 것

* 나란히 돌리는 겉껍질이 **끝난 코드(exit code)와 「검사 0」을 실패로** 셉니다.
  (저장소의 `test/browser/run.sh` 는 원래부터 이것을 봤는데, 제가 빨리 돌리려고
  쓰던 겉껍질이 안 봤습니다. 같은 눈으로 맞췄습니다.)
* `test/browser/run.sh` 에 **미리 확인**을 넣었습니다. playwright 를 못 찾으면
  같은 말을 125번 하는 대신 **한 번 말하고 멈춥니다.**

## 2. 화면 결함 3건 (PRODUCT DEFECT)

### ① 자정을 넘기면 「오늘」이 어제가 됩니다 — `RequestSheet`

수거 요청 창은 화면틀에 붙어 있어서 **닫아도 사라지지 않습니다.**
날짜 후보를 한 번만 계산해 두면, 요양병원 데스크처럼 화면을 켜 둔 채
쓰는 곳에서는 자정을 넘긴 뒤에도 **어제 날짜를 「오늘」이라고** 보여 줍니다.
그걸 고르면 **지난 날짜**가 희망일로 저장됩니다.

→ 창이 열릴 때마다 날짜를 다시 잡고, **지나간 날짜를 골라 둔 상태면 지웁니다.**
고르신 다른 것은 그대로 둡니다(실수로 닫으셨을 때 처음부터 다시 고르게
하지 않으려는 것입니다).

### ② 「PC 화면으로 보기」가 첫 화면에만 있었습니다

이 단추를 화면 맨 아래 칸(`PortalFooter`)에 뒀는데, 그 칸은 **첫 화면에만**
있습니다. 「이용 내역」이나 「고객지원」에서는 PC 화면으로 넘어갈 길이
없었습니다. → 화면틀로 올려 **어느 병원 화면에서든** 쓸 수 있게 했습니다.

(머리띠에는 두지 않습니다 — 0090 에서 단추가 다섯이 되자 병원 이름이 긴 곳에서
두 줄이 되고 「수거 요청」이 첫 화면 밖으로 밀렸습니다. 실측으로 확인한 것입니다.)

### ③ 창에서 창으로 넘어가면 화면이 영영 안 굴러갈 수 있었습니다

창이 열리면 뒤 화면 스크롤을 잠급니다. 예전 방식은 「열기 전 값을 기억했다
닫을 때 되돌리기」였습니다. 그런데 **증빙 → 이력**처럼 창에서 창으로 바로
넘어가는 길이 있고, 그때 두 창이 잠깐 겹칩니다. 나중 창이 앞 창이 걸어 둔
`hidden` 을 「원래 값」으로 기억했다가 닫을 때 되돌려 놓으면 — 화면이
영영 안 굴러갑니다. 병원 담당자에게는 그냥 **먹통**입니다.

겹치는 것은 Playwright 로 실제로 확인했습니다(닫는 창 하나 + 여는 창 하나가
동시에 잡혔습니다). → **세어서** 마지막 창이 닫힐 때만 풉니다.

## 3. 실계정 검사도 고쳤습니다 — 터질 자리에서 터질 뻔했습니다

`check_live_client.mjs` 는 **실제 운영 서버에 실계정으로** 들어가 보는
검사입니다. 자격이 없으면 조용히 건너뛰기 때문에 회귀에서는 늘 초록이었지만,
안에는 0089 에서 없어진 `#req-content` · `[data-req-sent]` 와
「자재·용기 칸을 누르면 `/portal/supplies` 로 간다」는 옛 전제가 남아 있었습니다.

**대표님이 실사 전에 돌려 보시는 그 순간에** 터졌을 검사입니다.
지금 화면에 맞춰 다시 썼습니다(칸 이름 11개 전부 실제 화면에 있는지 대조).

## 4. 여러 번 돌린 결과

같은 빌드에 대해 브라우저 회귀를 **3회** 돌렸습니다. 간헐 실패(flake)를
가려내려면 한 번으로는 모자랍니다.

| 회차 | 스위트 | 검사 | 실패 | 터진 스위트 |
|---|---|---|---|---|
| 1 | 125 | 4,623 | 0 | 0 |
| 2 | 125 | 4,623 | 0 | 0 |
| 3 | 125 | 4,623 | 0 | 0 |

세 회차의 검사 수가 **한 건도 다르지 않습니다** — 조건부로 건너뛴 검사도,
간헐 실패도 없었다는 뜻입니다.

새로 넣은 `check_portal93.mjs` (32건)가 보는 것:

* 두 번 빠르게 눌러도 **요청은 한 건**
* 서버가 실패하면 창이 안 닫히고 **고른 것이 그대로 남는다** · 알림 띠를 띄우지 않는다
* 다시 보내도 **여전히 한 건** (서버가 「이미 있음」으로 막아도 실패라고 하지 않는다)
* 날짜 후보가 **오늘 기준**이다
* 실수로 닫아도 고른 것이 남는다
* 창 8개 전부 열고 닫는 동안 **콘솔 오류 0**
* 창에서 창으로 넘어간 뒤에도 **화면이 굴러간다**
* 자료가 늦게 와도 「연결된 병원 정보를 찾을 수 없습니다」나 병원 고르기 화면이
  **번쩍이지 않는다**

## 5. 남겨 둔 것 (일부러)

**문의(`client_inquiries`)에는 저장시도 표가 없습니다.**
통신이 끊긴 뒤 다시 보내시면 같은 문의가 두 건 들어갈 수 있습니다.
요청·주문은 이미 막혀 있습니다(돈과 배차가 걸린 쪽입니다).
문의까지 막으려면 **칸 추가 + 고유 색인**이 필요해서 SQL 이 한 판 더 나갑니다.
안정화 회차에 대표님 손을 빌릴 일을 늘리지 않았습니다. 다음 SQL 때 같이
올리시면 됩니다. 금액에는 영향이 없습니다.
