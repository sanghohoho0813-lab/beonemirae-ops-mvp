# 0088 — 병원 Context 유지 (대표님 신고 수정)

## 대표님이 겪으신 것

> 비원종합병원 선택 → 필요한 물품 → **다시 병원 선택 화면** →
> 다시 선택 → **대시보드로 원점 복귀**

## 원인 — 한 줄이었습니다

0085 에서 병원을 `?client=<id>` 로 주소에 달았습니다.
그런데 포털 안의 메뉴 단추들은 이렇게 적혀 있었습니다.

```tsx
{ to: '/portal/supplies', label: '필요한 물품' }   // ← 물음표 뒤가 없습니다
```

메뉴를 누르는 순간 어느 병원인지가 사라집니다. 그러면 화면은 규칙대로
「어느 병원을 보시겠습니까」를 다시 묻고, 고르면 첫 화면으로 갑니다.
물품을 보러 가던 길이 지워집니다.

같은 이유로 **알림 · 제품 투어 · 「병원 화면에서 수락」**도 병원을 잃고
있었습니다.

## 「메뉴마다 물음표를 붙이자」로 고치지 않았습니다

붙이는 것을 한 군데라도 빠뜨리면 같은 일이 다시 납니다. 대신 **붙일 자리가
하나도 없는 구조**로 바꿨습니다 — 병원 id 가 경로 안에 들어갑니다.

| | 경로 |
|---|---|
| 직원 미리보기 | `/portal/c/<병원id>` · `/portal/c/<병원id>/supplies` … |
| 병원 계정 | `/portal` · `/portal/supplies` … (고를 것이 없습니다) |
| 병원 고르기 | `/portal/select?back=<보던 화면>` |

경로에 있으면 메뉴를 눌러도, 새로고침해도, 뒤로가기를 해도 안 지워집니다.
주소를 그대로 복사해 드려도 같은 화면이 열립니다.

> ⚠ `c` 한 글자를 넣은 이유 — `/portal/<id>` 로 두면 `/portal/report` 의
> `report` 가 병원 id 로 읽힙니다. 갈림길은 언젠가 반드시 잘못 갑니다.

포털 안의 **모든 이동이 `target.path(page)` 한 곳**을 지나갑니다.
NAV 항목에는 완성된 주소 대신 화면 이름만 둡니다 — 병원을 빠뜨릴 자리가
없습니다.

```ts
// src/lib/portalClient.ts
export function portalPath(clientId: string | null, page: PortalPage = ''): string
```

## 함께 고친 것

**읽는 중에는 아무 데도 안 보냅니다** (브리프 22 · 23)
첫 렌더에서 거래처 목록이 비는데, 그때 「못 찾았으니 고르세요」를 하면 메뉴를
누를 때마다 고르는 화면이 깜빡입니다. 「아직 안 읽었다」와 「정말 없다」를
`useLoadState()` 로 나눕니다.

**병원 고르기가 자기 주소를 가집니다**
예전에는 본문 자리에 목록이 끼어들었습니다. 이제는 「병원 변경」을 눌렀을
때만 옵니다. `?back=` 에 보던 화면을 담아 가므로, **리포트를 보다 병원을
바꾸면 새 병원의 리포트**가 열립니다.

**병원 계정이 남의 병원 주소를 직접 쳐도 자기 주소로 되돌립니다** (브리프 26)
서버(RLS)가 이미 남의 자료를 안 줍니다. 그래도 주소를 두면 주소창에 남의
병원 id 가 박힌 채 자기 자료가 보입니다 — 「내 화면에 저 병원 이름이 왜
있지」가 됩니다.

**화면 위에 「병원명 / 지금 화면」** (브리프 11)

**미리보기 띠가 폰에서 979px 이었습니다**
`flex-1` 은 basis 가 0 이라, 옆에 `shrink-0` 단추가 셋이 되자 글자칸이 0 에
가깝게 눌리면서 한국어가 **한 글자씩** 줄바꿈됐습니다. 그 바람에 「수거
요청」이 y=1,442px 로 밀렸습니다. → **171px · y=634px**

## 왕복이 실제로 도는가

`test/browser/check_e2e88.mjs` (38건)

다른 검사들은 **읽기**를 봅니다. 이 파일은 **왕복**을 봅니다. 그래서 서버
흉내를 「빈 배열을 돌려주는 것」이 아니라 **기억하는 것**으로 만들었습니다.
병원이 올린 요청이 진짜로 저장되고, 직원 화면이 그것을 읽고, 직원이 바꾼
상태를 병원 화면이 다시 읽어야 통과합니다.

| 흐름 | 확인한 것 |
|---|---|
| 병원 수거 요청 | 서버에 실제로 남음 · 그 병원 것으로 · 희망일/유형/예상량 그대로 |
| 직원 요청함 | 그 요청이 뜸 · 병원 이름 · 희망일 · 「병원 어림 140kg」 |
| 직원이 상태 변경 | 서버에 남음 (`일정 반영`) |
| 병원 화면 | 상태가 바뀜 · **알림에도 뜸** · 비원미래 회신이 그대로 보임 |
| 수거 완료 | 이력 27 → 28건 · 합계 증가 · **실제 137kg** (병원이 어림한 140 이 아니라) |
| 자재 주문 | 30L 박스 10개 → 서버 저장 → 요청 → 확인 → 준비 → 전달예정 → 전달완료 |
| 남의 병원 | 요청·회신·주문 상태가 **한 줄도 안 보임** |

> ⚠ 화면에 그럴듯한 글자가 떴는지가 아니라 **저장소에 무엇이 남았는지**를
> 함께 봅니다. 화면만 보면 「보내지도 않고 보냈다고 하는」 결함을 못 잡습니다
> (0055 에서 실제로 있었던 일입니다).
