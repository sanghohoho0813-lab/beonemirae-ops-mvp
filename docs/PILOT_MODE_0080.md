# 0080 — Pilot 전달 전 화면 단순화

> 대표님: 「송현주 이사님 / 송현근 대표님이 처음 시스템을 쓸 때 불필요한
> 기능·알림·경고 때문에 헷갈리지 않도록, 지금 당장 실제로 쓸 핵심 업무만
> 보이게 만드는 것이 목표다. 현재 기능은 가능하면 삭제하지 말고, Pilot 동안
> 숨기거나 비활성화하는 방향을 우선해줘.」

## 무엇도 지우지 않았습니다

내린 것은 **화면**뿐입니다. 코드도, 표도, 지금까지 쌓인 요청 이력도 그대로
있습니다. 스위치는 한 곳입니다.

```ts
// src/lib/pilotMode.ts
export const PILOT_HIDDEN: PilotHidden = {
  clientRequests: true,   // 병원 수거요청 — 내려 둠
  supplies: false,        // 소모품 주문·판매 — 실사에서 보여 드릴 화면이라 켬 (0081)
}
```

> **0081** — 대표님: 「소모품주문 화면은 다시 띄워줘. 실사 당시에 보여줘야
> 되거든.」 위 한 줄만 `true` → `false` 로 바꿨습니다. 화면 코드도 검사도
> 손대지 않았고, 건너뛰던 검사 22건이 **저절로 다시 돌기 시작했습니다.**
> 아래 표의 `supplies` 줄은 지금은 해당되지 않습니다.

`false` 로 바꿔 배포하면 끝입니다. **화면 어디에도 따로 고칠 곳이 없습니다.**
그때 과거 요청·처리완료 이력도 그대로 다시 보입니다.

## 어디를 내렸나

| 스위치 | 내려간 곳 |
| --- | --- |
| `clientRequests` | 사이드바·더보기 메뉴 · `/requests` 주소 자체 · 대표 첫 화면의 「급한 요청이 반복됩니다」 띠 · 「병원 요청 → 처리 → 제안 → 수락 → 매출」 전환 카드 · 오늘 일정 위의 요청 줄 · 거래처 상세의 「요청·알림」 탭 · 사용 방법 안내의 요청 단계 |
| ~~`supplies`~~ | ~~사이드바·더보기 메뉴 · `/supplies` 주소 자체 · 설정 화면의 「소모품 판매가가 비었습니다」 줄 · 사용 방법 안내의 소모품 단계~~ — 0081 에서 다시 켰습니다 |

병원 포털(`/portal/supplies`)은 **그대로 둡니다** — 병원 담당자 화면이고,
Pilot 계정(대표·이사·기사)과 무관합니다.

### 막는 자리를 하나로

`canAccess()` 한 곳에서 막습니다. 메뉴에서만 빼면 옛 링크나 주소를 직접 칠 때
그대로 열려서 「메뉴엔 없는데 왜 열리지」가 됩니다.

```ts
// src/lib/access.ts
if (isHiddenRoute(path)) return false   // ⚠ admin 전체 허용보다 **먼저**
if (role === 'client') return isPortalPath(path)
if (role === 'admin') return true
```

⚠ 순서가 중요합니다. `admin` 은 아래에서 전부 통과라, 뒤에 두면 **대표님
화면에서만** 그대로 보입니다.

## 함께 고친 실제 결함 — 「처리했는데 왜 아직 남아 있지」

대표님: 「현재 완료된 요청이 계속 `미처리`처럼 집계되는 실제 로직 오류가
있다면, 숨기기만 하지 말고 원인은 확인해서 고쳐줘.」

**있었습니다.**

0076 에서 「요청을 잠시 내려 두기」를 만들었습니다. 그런데 그때 고친 것은
`openRequests` **한 곳뿐**이었고, 「급한 요청이 반복됩니다」를 계산하는
`urgentRisks` 는 그대로 두었습니다. 그래서

- 대표님이 **내려 둔** 요청이 첫 화면 경고에는 계속 떴습니다
- **처리 완료**한 요청까지 그 경고에 섞여 셌습니다

두 가지 모두 고쳤습니다.

```ts
// src/lib/urgentRisk.ts
const reqs = (data.requests ?? []).filter(
  (r) =>
    isUrgentKind(r) &&
    r.createdAt.slice(0, 10) >= from &&
    clients.has(r.clientId) &&
    r.status !== '처리 완료' &&                       // ← 끝난 것은 안 셈
    !(r.snoozedUntil && r.snoozedUntil > t),          // ← 내려 둔 것도 안 셈
)
```

⚠ **이 고침은 Pilot 스위치와 무관합니다.** 스위치를 꺼도 그대로 남습니다 —
숨겨서 안 보이게 한 것이 아니라 계산이 틀렸던 것입니다.

⚠ 이력을 지우는 것이 아닙니다. 요청 화면에는 그대로 다 있습니다. 이 띠는
「**지금 손대야 하는 곳**」을 말하는 자리라 거기서만 뺐습니다.

## 시작하기 체크리스트 — 한 줄로

수거를 **한 번이라도 해 본** 회사에서는 큰 카드가 한 줄로 줄어듭니다.

```
아직 안 하신 설정이 1가지 있습니다 — 도입 전 기준값 입력          >
```

- 없애지 않았습니다. 남은 항목이 **진짜로 남아 있기** 때문입니다
- 기준은 「수거를 해 봤는가」입니다. 그때부터는 처음 세팅하는 사람이 아니라
  **매일 쓰는 사람**입니다
- 아직 한 번도 안 해 봤으면 큰 카드가 그대로 나옵니다

## 확인한 것

`test/browser/check_pilot80.mjs` — 47건. 대표님이 실제로 겪으신 상황(더원요양병원
급한 요청 3건 + 이미 굴러가는 회사)을 그대로 만들어 놓고 봅니다.

- 대표(admin)·이사(office)·기사(field) 세 화면 모두에서 요청·소모품 자취가 없다
- **주소를 직접 쳐도** 안 열린다
- 요청 이력은 서버에서 **계속 내려온다** — 화면에만 안 그린다
- 스위치가 `src/lib/pilotMode.ts` 한 곳에 있고, 화면 코드는 지워지지 않았다
- `/today /collection /clients /materials /history /billing /receivables` 가 그대로 열린다
- 어느 화면에도 내려 둔 곳으로 가는 링크가 없다

### 옛 검사들은 어떻게 했나

요청·소모품 화면을 여는 옛 검사는 **지우지 않고 건너뜁니다**
(`test/browser/_pilot.mjs`). 그 파일은 화면 코드와 **같은 `pilotMode.ts` 를
읽습니다** — 스위치를 되돌리면 검사도 저절로 다시 돕니다.

```
SKIP | ⑤ 요청 화면의 「날짜 잡기」 — Pilot 동안 「병원 요청」을 화면에서
       내려 두었습니다 (src/lib/pilotMode.ts). 다시 켜면 이 검사도 같이 돌아옵니다.
```

기대값을 「안 보이는 게 맞다」로 바꿔 두지 않았습니다. 그렇게 하면 다시 켤 때
아무도 봐 주지 않은 코드가 그대로 대표님 첫 화면에 올라옵니다.

같은 이유로 `urgentRisks` **계산 자체는 비우지 않았습니다.** 안 그리는 것은
`components/UrgentRisk.tsx` 가 정합니다 — 계산을 비워 버리면 「이 계산이
맞는가」를 확인할 길이 같이 없어집니다.
