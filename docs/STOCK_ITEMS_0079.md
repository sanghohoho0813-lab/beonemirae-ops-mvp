# 0079 — 규격별 재고 (2L 합성수지 … 기저귀비닐 40L)

> 대표님: 「자재 관리 목차에서 2L 합성수지 ~ 기저귀비닐 40L 까지도 수량을
> 실시간으로 확인할 수 있게 해줘. 지금은 골판지 전용박스부터 합성수지
> 바늘통까지 4개밖에 없어서 불편해.」

## 왜 4개뿐이었나 — 화면 문제가 아니었습니다

서버가 **숫자를 넉 장만** 들고 있었습니다. `office_stock` 표에 칸이 네 개
(골판지 · 합성수지 · 봉투 · 바늘통)뿐입니다.

0075 에서 **공급은** 13 규격으로 받게 됐는데, **재고는** 그 13 개를 네 칸으로
합쳐서 깎았습니다. 그래서 「63L 박스가 몇 개 남았나」는 서버 어디에도 없는
값이었습니다. 화면을 아무리 고쳐도 나올 수 없었습니다.

## 제일 중요한 결정 — 쪼개지 않았습니다

골판지 480 개가 **63L 몇 개, 35L 몇 개인지 아무도 모릅니다.** 그럴듯하게
나눠 넣을 수는 있었지만 그 숫자는 첫날부터 틀린 값이고, 대표님은 그것을 믿고
발주하시게 됩니다.

그래서 세어 보기 전까지는 **「아직 안 세어 봄」**입니다 — 화면에도 그렇게
적히고, DB 에도 `null` 로 들어갑니다. **0 개와 다릅니다.**

| 상태 | DB | 화면 |
| --- | --- | --- |
| 한 번도 안 셌다 | `qty is null` | 「아직 안 세어 봄」 (노란 칸) |
| 세었다 | `qty = 120` | `120개` |

한 번 세어 넣으시면 그때부터 **공급·입고에 맞춰 저절로 따라갑니다.**

## 무엇이 생겼나

### 서버 (`supabase/proposals/PROPOSAL_0079_stock_items.sql`, 판 77 → 79)

| 대상 | 하는 일 |
| --- | --- |
| `office_stock_items` | 규격별 재고 13 줄. `qty null = 모름` |
| `material_transactions.item_key` | 원장에 **규격**을 적는 칸. 기존 `item`(네 칸)은 뜻을 안 바꿉니다 |
| `count_stock_item(규격, 센 수, 이유)` | 창고에서 센 수로 **정합니다** (더하기가 아닙니다) |
| `receive_stock_items(규격들, 메모)` | 규격으로 입고. 네 칸 합계도 같이 늘어납니다 |
| `supply_materials_items` | 0075 본문 그대로 + **한 줄만** — 원장을 규격으로 남깁니다 |
| `apply_item_stock` 트리거 | `materials` 표에 붙습니다. **규격별 재고를 깎고 되돌리는 곳은 여기 한 곳뿐입니다** |

### 왜 트리거인가 — 자재를 주는 길이 두 갈래입니다

- `supply_materials_items` — 자재 관리 화면
- `complete_collection` — 수거 입력의 「주고 온 자재」

둘 다 결국 `materials` 표에 한 줄을 넣고, 그 줄의 `items` 에 규격이 있습니다.
그래서 **그 자리 한 곳**에서 깎습니다. 함수 두 개에 같은 계산을 넣으면 언젠가
한쪽만 고쳐집니다.

무르기(`revert_collection`)는 그 줄을 **지웁니다.** 그때 네 칸이 되돌아오므로
규격별도 같이 되돌립니다 — 안 그러면 무를수록 규격별만 줄어듭니다.

**건드리지 않은 것** — 재고 한도 검사, 중복방지(`request_id`), 정산용 옛 3칸,
감사기록, RLS. 검사로 하나씩 확인했습니다(⑨번 블록).

### 권한

- 세기·입고 → **사무실·관리자만**
- 공급 → 기사님도 (현장에서 직접 건네줍니다 — 예전 그대로)
- 표를 직접 고치는 길은 **없습니다.** 쓰기 정책을 두지 않아, 직접 `update` 하면
  0 줄만 바뀝니다. 그래야 원장에 반드시 같이 남습니다.

### 화면

`자재 관리` → 「사무실 자재 재고」 넉 장 카드 **아래**에 「규격별 재고」가
붙습니다. 넉 장은 **칸 합계**, 아래가 그 **안쪽 내역**입니다.

- 13 규격을 재고 칸별로 묶어서 보여 줍니다
- 규격마다 `세기` / `고치기`
- 입고도 13 규격으로 적습니다 (예전에는 「골판지 100개」까지만 됐습니다)
- 판 78 이하에서는 **아예 안 그립니다** — 없는 것을 0 으로 채우지 않습니다

## 확인한 것

- `test/db/db_items79.mjs` — 격리 DB 48건
- `test/browser/check_stockitems79.mjs` — 브라우저 41건 (PC 1280px · 폰 390px · 판 78 되돌림)

특히 이 두 가지를 검사로 못박아 두었습니다.

- 처음에는 13 개 **전부 「모름」** — 0 으로 적힌 규격이 하나도 없다
- 안 세어 본 규격은 공급·입고 뒤에도 **여전히 「모름」** — 0 으로 만들지 않는다
- **수거 입력**으로 준 자재도 규격별에서 빠지고, **무르면 되돌아온다**
- 규격을 안 보내는 옛 흐름(`supply_materials`)은 규격별을 건드리지 않는다 —
  어느 규격인지 모르니 손대지 않는 것이 맞습니다
