# 0081 — 화면 색(테마) 바꾸기

대표님 지시: 「클릭 한 번으로 바꿀 수 있는 고급 테마 변경 기능」.
시안 9장을 계열로 묶어 **9가지**를 넣었습니다.

---

## 1. 어떻게 만들었나 — 화면은 한 줄도 안 바꿨습니다

지금 코드는 색을 거의 전부 팔레트 토큰(`navy` / `teal` / `accent`)으로만 쓰고
있었고, 손으로 적어 둔 색은 10곳뿐이었습니다. 그래서 **팔레트를 CSS 변수로
빼는 것**만으로 끝났습니다.

```
tailwind.config.js   navy-400: 'rgb(var(--c-navy-400) / <alpha-value>)'
src/themes.css       [data-theme="forest-sage"] { --c-navy-400: 106 116 100; ... }
```

`text-navy-400` · `bg-teal-500` 을 쓰던 **3,000여 곳이 그대로** 테마를 따라갑니다.
차트도 전부 Tailwind 클래스로 그려져 있어 같이 따라옵니다.
`<html data-theme="...">` 한 글자만 바뀌고, 배치·메뉴·정보 구조·하는 일은
**하나도 안 건드렸습니다.**

## 2. 색을 바꾸면서 글자가 안 보이게 되지 않는 이유

WCAG 대비는 **오로지 밝기(상대휘도)로만** 계산됩니다.
그래서 테마마다 **각 단계의 밝기를 기준 팔레트와 같게 두고 색상만** 바꿉니다.

> 0080 에서 대비 미달을 173개 → 0개로 만들었는데,
> 그 결과가 **아홉 테마 전부에서 그대로** 유지됩니다.

`scripts/gen_themes.mjs` 가 값을 만들고 그 자리에서 검산합니다 —
**9테마 × 18짝 = 162 검사, 미달 0.**

예외는 하나뿐입니다. 금색처럼 **밝아서 흰 글자가 안 읽히는** 색은 밝기를
낮춰 어둡게(브론즈로) 잡았습니다. 색을 위해 가독성을 깎지 않습니다.
그 결과 **새 테마 8개가 기본 테마보다 대비가 좋습니다**(13개 vs 19개) —
기본 테마의 브랜드 파랑은 그대로 두었기 때문입니다.

## 3. 뜻이 붙은 색은 뜻을 지킵니다

상승/완료 = 초록, 주의 = 노랑, 하락/경고 = 빨강, 정보 = 파랑.
이건 **뜻을 지고 있는 색**이라, 테마에 맞춘다고 초록을 빨강 쪽으로 돌리면
「완료」가 「경고」로 읽힙니다.

그래서 색상을 테마 쪽으로 **최대 ±14° 까지만** 끌어옵니다. 톤은 맞고 뜻은
그대로입니다. 검사에서 색상각이 제 무리를 벗어나면 실패로 잡습니다
(초록 100~190° · 노랑 20~60° · 빨강 330~15° · 파랑 180~230°).

## 5. 어디서 바꾸나

- **오른쪽 위 「화면 색」 단추** — PC·폰·병원 포털 모두. 누르면 창이 열리고,
  누르는 즉시 바뀝니다. 「적용」 단추를 따로 두지 않았습니다.
- **설정 → 화면 색** — 「화면 글자 크기」 바로 위. 둘 다 「보이는 것」을
  맞추는 설정이라 한자리에 모아 두었습니다.

고른 색은 **이 기기에** 저장됩니다(localStorage). 새로고침해도, 다른 화면으로
가도, 다시 접속해도 그대로입니다.
React 가 뜨기 **전에** 붙이므로 켤 때 화면이 번쩍이지 않습니다(index.html).

> ⚠ **다른 기기까지는 안 따라갑니다.** 계정에 저장하려면 `profiles` 에 칸을
> 하나 늘리는 SQL 이 필요한데, 운영 DB 를 바꾸는 일이라 대표님 승인 없이
> 만들지 않았습니다. 원하시면 SQL 을 따로 올리겠습니다.

## 6. 그 김에 잡힌 결함

- **주 단추가 흰 바탕에 흰 글자가 됐습니다(대비 1:1).**
  `@import` 를 `@tailwind` **뒤에** 뒀더니 빌드 결과에서 테마 변수가 통째로
  빠졌고, `rgb(var(--c-teal-500) / 1)` 이 잘못된 값이 되어 속성 자체가
  버려졌습니다. CSS `@import` 는 파일 맨 앞이어야 합니다.
- **폰에서 고르는 창이 머리띠 안에 갇혔습니다.**
  이 단추가 있는 폰 머리띠에 `backdrop-blur` 가 걸려 있는데, `backdrop-filter`
  가 걸린 요소는 그 안의 `position: fixed` 요소의 **기준 상자**가 됩니다.
  그래서 시트가 화면(844px)이 아니라 머리띠(126px) 기준으로 그려져 위로
  잘렸고, **아홉 개 중 한 개만 보였습니다.** 이 시트만 문서 맨 바깥에
  그리도록 했습니다(공용 Modal 은 그대로 둡니다 — 다른 화면은 멀쩡합니다).
- **폰에서 아래 세 개는 스크롤해야 나왔습니다.** 고르는 창에서 스크롤하게
  만들면 있는 줄 모르고 지나갑니다. 폰에서만 설명 한 줄을 접어
  **아홉 개가 스크롤 없이** 다 보이게 했습니다.
- **사이드바가 아홉 테마에서 전부 거의 같은 검정이었습니다.** 어두운 단계의
  밝기를 오히려 낮춘 제 실수입니다 — 밝기가 0에 가까우면 색상이 안 보입니다.
  시안처럼 「색이 보이는 어두움」이 되게 올렸습니다(흰 글자 대비 19:1 → 15:1,
  여유 충분).
- **플럼이 「고급」이 아니라 「화려」했습니다.** 자홍이 아니라 자두가 되도록
  채도를 크게 낮추고 더 어둡게 잡았습니다. 버건디도 같이.

## 7. 남긴 검사

`test/browser/check_theme.mjs` — **검사 128건.**

1. 아홉 가지가 PC·폰에서 **실제로** 적용되는가 (그리고 서로 **다른** 색인가 —
   변수가 안 붙어도 화면은 멀쩡히 그려지므로 「다르다」까지 봐야 합니다)
2. 오른쪽 위 단추 → 아홉 개 → 눌러서 바뀜 → 새로고침·화면 이동 후에도 유지 →
   **첫 그림부터** 붙어 있음(번쩍임 없음)
3. 저장된 값이 모르는 이름이면 기본색으로
4. 어떤 색을 골라도 **대비·작은 글자·손가락 기준이 기본색보다 나빠지지 않음**
5. 뜻이 붙은 색의 색상각이 제 무리 안에 있음

`@import` 를 원래 자리로 되돌려 이 검사가 실제로 빨간불이 되는 것까지
확인했습니다.
