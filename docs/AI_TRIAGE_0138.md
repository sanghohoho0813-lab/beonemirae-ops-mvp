# 0138 · 병원 요청 AI 분석 — 첫 번째 실제 AI 업무 보조

> **상태: 코드 완료 · 실제 외부 AI 호출 미검증.** 이 저장소와 작업 환경에는 비원미래의 AI 키가
> 없습니다. 키 등록 · 함수 배포는 `supabase/functions/ai-triage/README.md` 의 절차로 대표님이
> 합니다. 그 전까지 화면은 실패를 그대로 보여 주고 기록하며, 가짜 결과를 만들지 않습니다.

## 한 줄 흐름

**병원 요청 → AI 분석 → 직원 확인 → 실제 처리**

병원이 포털에 올린 요청 하나를 외부 LLM 이 읽고 **요청 종류 · 긴급도 · 요약 · 핵심 요구사항 ·
회신 초안 · 판단 근거**를 제안합니다. 직원이 확인 · 수정해 회신하고, 상태 변경 · 일정 확정은
직원이 따로 합니다.

## 비원미래 AX 의 AI 기준 (이번부터)

| 맡는 쪽 | 하는 일 | 예 |
|---|---|---|
| **Rule / DB** | 사실과 계산 | 일정 · 배차 · 재고 · 정산 · 미수 · AX 코치 추천 · 성과 지표 |
| **LLM** | 비정형 문장의 이해 · 요약 · 분류 · 문장 작성 | 병원 요청 글 분석 · 회신 초안 |

- LLM 은 계산 결과를 덮어쓰거나 DB 에 없는 사실을 만드는 판단자가 아닙니다.
- 다음 후보(「AI 오늘의 운영 브리핑」)도 같은 방식입니다: **DB/Rule 이 사실 후보를 만들고 →
  LLM 은 그것을 3개 정도로 요약**. LLM 이 스스로 문제를 찾아내는 자유형 Agent 는 쓰지 않습니다.
  (이번 작업에서는 만들지 않았습니다 — ai-triage 가 운영에서 안정적으로 도는 것이 먼저입니다.)

## AI 가 읽는 것 / 절대 바꾸지 않는 것

- 읽는 것: 그 요청의 글(전화번호 · 주민번호 · 메일 가림 · 2,000자), 병원이 고른 종류, 급함 표시, 희망일
- 보내지 않는 것: 병원명 · 요청자 · 매출 · 미수 · 정산 · 전체 거래처 · 수거 이력
- 바꾸지 않는 것: 요청 상태 · 회신 전송 · 일정 확정 · 배차 · 수거량 · 재고 · 정산 · 그 밖의 운영 DB
  (함수가 쓰는 곳은 `ai_calls` 하나)

## 발표 시연 (1~2분)

**미리 할 것**: 키 등록 · 배포 · 「배포 후 확인」 1회 · 시연 계정 두 개(병원 · 사무실) 로그인 확인.
시연 요청을 운영 실적에 섞지 않으려면 시연용 거래처로 하거나, 끝나고 `kind` 로 구분된 것을 확인합니다.

1. **병원 포털**(폰) → 「긴급수거 요청」 → 「폐기물이 예상보다 빨리 찼습니다. 가능하면 내일 오전에
   부탁드립니다.」 → 요청하기 → 「요청이 접수되었습니다」 (15초)
2. **직원 화면** → 고객 요청 → 방금 요청이 맨 위 → 「회신 남기기」 (10초)
3. **「AI 분석 실행」** → 실제 AI 가 분석 (2~10초) → 종류 · 긴급도 · 요약 · 회신 초안 (20초 설명)
   - 말할 것: 「병원 요청 내용을 AI 가 분석해 요청 유형과 긴급도를 정리하고 담당자의 회신 초안을 제안합니다.」
4. **「초안 사용」** → 한 줄 고치기 → 「회신 저장」 (15초)
   - 말할 것: 「최종 판단과 일정 확정은 담당자가 합니다. AI 는 상태를 바꾸거나 병원에 보내지 않습니다.」
5. (필요하면) 요청 줄에서 상태를 「확인 중」으로 — 담당자가 직접 (5초)
6. **병원 포털** → 요청 내역 → 그 요청 → 「담당자 안내」에 회신 (10초)

### 쓰지 않는 표현
「AI 가 자동 배차합니다」 · 「AI 가 최적 수거경로를 결정합니다」 · 「AI 가 의료폐기물 발생량을
예측합니다」 · 「전체 업무가 AI 로 자동화되었습니다」 — 지금 구현이 아닙니다.
