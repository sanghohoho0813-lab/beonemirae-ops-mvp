## 1. 세 칸 — 기본은 「요약」

| 칸 | 주소 | 무엇이 있나 |
|---|---|---|
| **요약** (기본) | `/performance` | ① 기업 성장 현황 → ② AX 로 확인된 변화 (최대 3장) → 업무 재현시험 → 「아직 측정하지 않은 항목 N개」(접힘) → ③ 다음 할 일 (최대 3개) |
| 측정 근거 | `/performance?tab=basis` | 지금 집계에 들어간 자료(진단) · 표본의 폭 · 내부 표시 기준 · 도입 전 실제 업무 · A 업무 효율 지표 카드 · B 자동화 · 업무·매출·고객·확장 AX 패널 · C 매출 · D 사업 확장 · 성장→병목→AX→측정→투자→목표 사슬 |
| 설정 | `/performance?tab=settings` | 실증 시작일·기준값(설정 화면으로) · 도입 후 같은 범위 조사(관리자) · **업무 재현시험 기록** · 운영 변화 기록 · 엑셀 한 줄 안내 |

요약 카드를 누르면 측정 근거 칸의 해당 계산으로 갑니다. 세부는 없애지 않았고, 기본 펼침만 아닙니다.

### 기본 화면에서 덜어낸 것 (측정 근거 칸으로 옮김)

- 표본의 폭 한 줄 (입력한 날 · 병원 · 기사 · 커버리지 · 누락률) 과 「대표 성과값 기준에 모자란 것」
- 실증 진행 단계(내부 표시 기준 30건 등) 막대
- 도입 전 실제 업무 조사표 · 도입 전 → 도입 후 일하는 방식 표
- 지표 카드 6장(입력 소요시간 · 사무업무 시간 · 반복 입력 · 취소 후 재입력 · 하루 처리 건수 · 문서 시간) 의 계산식·출처·제외 조건
- 자동화(B) · 매출(C) · 사업 확장(D) · 업무·매출·고객·확장 AX 패널 · 성장 사슬
- 「근거가 없으면 숫자를 만들지 않습니다」 같은 되풀이 경고문 — 요약에는 한 번도 없음. 대신 숫자 옆의 넉 자.
- 옆 메뉴 설명: 「측정값 · 같은 범위 비교 · 표본의 폭」 → 「회사 현황 · AX 로 확인된 변화 · 다음 할 일」
  (0108 에서 폰 「더보기」 길이를 지키려고 「회사 현황 · 확인된 변화 · 다음 할 일」로 한 번 더 줄였습니다. 화면 안 부제는 그대로입니다.)

## 3. 요약에 무엇이 나오는가 (`src/lib/perfSummary.ts`)

- **카드는 값이 있는 것만, 최대 3장.** 우선순위: 사무업무 시간(같은 범위 실측이 있을 때만) → 입력 시간 → 자동 반영 → 당일 입력률 → 다시 적는 횟수 → 포털 병원 → 처리시설 대기 → 계기판 km.
- 표본이 작아도 실제로 잰 값이면 보여 줍니다 (`MIN_SAMPLES` 3 → 1). 30건 같은 임의 건수 기준으로 숫자를 감추지 않습니다. 다만 비교 범위가 다르면 개선율은 만들지 않습니다 — 입력 시간 카드에 「도입 전 사무시간과 범위가 달라 개선율은 내지 않음」.
- 실제로 잰 0 과 나빠진 값은 카드에 그대로 둡니다 (나빠지면 붉은 숫자, 「N% 늘어남」).
- 값이 없는 항목은 「아직 측정하지 않은 항목 N개」로 묶고, 펼치면 항목마다 이유 한 줄.
- **당일 입력 완료율**은 현장 입력이 1건이라도 있을 때만 카드가 됩니다. 이관(migrated)·시연·시드 일정은 이 비율의 분모에서도 뺍니다 (0106 A 의 제외 기준과 같음 — 이번에 `workAx` 에서 빠져 있던 것을 바로잡음).
- **다음 할 일** 최대 3개, 순서: 못 읽은 자료 → 현장 입력 0건 → 기준값 비어 있음(관리자) → 재현시험 없음 → 도입 후 같은 범위 조사 없음(관리자) → 엑셀 한 줄 5일 미만 → AX 시작일 미기록. 관리자만 할 수 있는 일은 사무실 계정에 안 보입니다.

## 4. 왜 숫자가 안 보였나 — 「자료 미확인」과 「실제 사용 없음」을 가릅니다

대표님 화면의 「연습 입력 6건 제외 · 실제 현장 0건 · 도입 전 기준값 미입력」은 세 가지가 섞인 것이었습니다.

| 보인 것 | 실제 뜻 | 화면이 이제 하는 말 |
|---|---|---|
| 연습 입력 6건 제외 | 실증 시작일(2026-08-29) **이전** 입력. 자료는 읽혔음 | 「실제 사용 없음 — 실증 시작일 2026-08-29 이후 현장 입력 0건」 + 「전체 N건 = 현장 0 · 연습 6 · 시연 · 취소」 |
| 실제 현장 0건 | 8/29 이후 기사 입력이 아직 없음 | 다음 할 일 1번 「기사님이 수거 입력을 시작」 |
| 도입 전 기준값 미입력 | 못 읽은 것이 아니라 **아직 안 넣은 것** (설정에서 1분) | 「도입 전 기준값 미입력 — 자료를 못 읽은 것이 아니라 아직 안 넣은 것입니다」 · 다음 할 일 「기준값 채우기」 |

- 표를 못 읽으면 (기준값 표 · 실증 시작일 표) `missingParts` 에 남고, 진단 첫 줄이 「자료 미확인 — 읽지 못한 자료 N건」이 됩니다. 이전에는 이 두 표의 읽기 실패가 기록되지 않아 **조용히 0** 이었습니다 — 이번에 바로잡음.
- 연습 기록을 실제로 바꾸는 것은 시스템이 하지 않습니다. 시작일을 앞으로 옮기면 실제로 세지만, 그 결정은 대표님이 설정에서 합니다 (화면에 그대로 적음). 숫자를 늘리려고 분류·시작일을 바꾸지 않습니다.
- 도입 후 조사값을 **추정(직접 입력)** 으로 넣어 두었다면 (지금 11.7분 · 91시간) 값과 출처는 보존하고 실측 비교에서는 뺍니다. 그래서 「0% 단축」이 생기지 않고, 「아직 측정하지 않은 항목」에 「11.7분은 추정이라 실측 비교에서 제외 — 이사님 같은 범위 조사가 들어오면 견줌」이라고 적힙니다.

## 5. 업무 재현시험 (`src/lib/trials.ts` · `src/components/TrialCard.tsx`)

현장 성과가 쌓이기 전에 **오늘** 얻을 수 있는 초기 측정값입니다.

| 어떤 일 | 예전 방식 | 시스템 방식 |
|---|---|---|
| 거래명세서 작성 | 엑셀 | 월말 청구 |
| 수거 건 입력·정리 | 수기·카톡·엑셀 | 수거 입력 화면 |
| 병원 요청 접수·처리 | 전화·카톡 | 고객 요청 화면 |

- 같은 자료 · 같은 결과물 · 실제로 잰 시간(분)과 오류 건수만. 두 시간 모두 0 이나 빈칸이면 저장을 막습니다.
- 저장은 사용자 피드백 표(`dev_requests`, 주제 「업무 재현시험」)에 한 줄 — 새 표·SQL 없음. 형식: `trial:날짜|과제|old=분,오류|new=분,오류 › 메모`.
- 요약에는 과제별 중앙값 「25분 → 9분 · 64% 단축 · 1회 · 오류 1→0」으로, **업무 재현시험** 표시를 달고 현장 카드와 따로 보입니다. 회사 전체 절감·연간 절감액으로 확대하지 않습니다.
- 사무실·관리자 계정이 설정 칸에서 기록합니다. 대표님 첫 시험: 8월 거래명세서 한 장 — 10분이면 첫 측정값이 생깁니다.
