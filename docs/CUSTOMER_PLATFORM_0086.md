# 0086 · 0087 — 병원 고객 포털 2차 고도화

대표님이 주신 2차 브리프의 네 가지 목표에 맞춰 한 일과, **하지 않은 것과 그 이유**를
적어 둡니다.

---

## 대표님이 실행하실 SQL

`supabase/proposals/PROPOSAL_0087_request_detail.sql` **한 개**입니다.

Supabase SQL Editor 에 붙여 넣고 실행하시면 됩니다. 여러 번 실행해도 결과가 같습니다.
맨 아래 확인 문장 세 줄이 각각 이렇게 나오면 정상입니다.

| 확인 | 나와야 하는 값 |
|---|---|
| 칸 두 개 생김 | `t` |
| 판 번호 | `87` |
| 저희가 채워 넣은 값 | `0` |

**무엇이 바뀌나** — `client_requests` 표에 칸 두 개가 생깁니다.

- `waste_type` — 병원이 고른 폐기물 유형 (의료폐기물 / 일회용기저귀)
- `expected_kg` — 병원이 어림한 배출량

지금까지 배차가 요청을 받고 **병원에 다시 전화해서 묻던** 두 가지입니다.
둘 다 비워 둘 수 있고, 비면 `null`(모름)로 남습니다. 기존 요청은 건드리지 않습니다.

⚠ **실행 전에도 화면은 그대로 돕니다.** 판이 87 미만이면 요청 창에서 이 두 줄을
아예 묻지 않습니다 — 적어 놓고 저장이 안 되는 칸을 만들지 않습니다.

## ① 관리자 ↔ 병원 화면 왕복 (0085)

| 브리프 | 한 일 |
|---|---|
| `← BUSINESS AX로 돌아가기` | 미리보기 띠의 단추. `navigate('/')` 명시 경로입니다 — 브라우저 뒤로가기가 아닙니다 |
| 병원 계정에는 안 보이게 | `usePortalClient()` 가 role 로 가릅니다. 병원 계정에는 띠 자체가 렌더되지 않습니다 |
| 관리자 미리보기 표시 | 「고객 화면 미리보기 · ○○병원」 + 「비원미래 전체 자료가 아닙니다」 |
| 거래처 상세 → 그 병원 화면 | `/portal?client=<id>` — **그 거래처의 실제 자료**입니다 |

**고친 결함** — 포털 일곱 곳이 `data.clients[0]` 을 「우리 병원」으로 쓰고 있었습니다.
병원 계정은 RLS 가 한 곳만 돌려주므로 맞았지만, 직원 계정에는 전체가 돌아오므로
**가나다순 첫 병원이 모든 직원에게 고정 노출**됐습니다. 브리프가 금지한 그 상태입니다.

직원이 아직 병원을 안 골랐으면 **아무 병원도 안 보여 주고 묻습니다.** 첫 병원을 슬쩍
띄우면 대표님이 그것을 「지금 보려던 그 병원」으로 읽으십니다.

### 「분석」 칸에 **AI 라고 적지 않은 이유**

대표님 브리프: *「실제 AI API가 연결되어 있지 않으면 fake AI 결과를 생성하지 않는다.
현재는 규칙 기반 insight라도 괜찮다 … 실제 분석 방식이 rules 기반이라면 코드상 명확히
구분한다.」*

`src/lib/portalInsight.ts` 는 **뺄셈과 나눗셈뿐**입니다. 모형도 확률도 없습니다.
그래서 화면 제목 옆에 「수거 기록으로 계산 · AI 아님」이라고 붙여 두었습니다.
나중에 실제 모형이 붙으면 그때 이름을 바꾸면 됩니다.

지금 말하는 것 네 가지 — 전부 **근거 숫자를 함께** 답니다.

1. 이번 달 배출량이 평소와 얼마나 다른가
   ⚠ 이번 달은 아직 안 끝났으므로, 지난 달들을 **같은 날짜까지 잘라** 비교합니다.
   안 그러면 매달 「줄었습니다」만 나옵니다.
2. 수거 간격이 고른가 (계약 수거주기와 실제가 다르면 병원이 먼저 알아야 합니다)
3. 지난달 수거 횟수의 변화
4. 배출자 교육을 받은 지 얼마나 됐는가 (`educationAt` 이 **있을 때만**)

⚠ 표본이 3개월치가 안 되면 **아무 말도 하지 않고**, 왜 아직 없는지만 적습니다.
수거 두 번 하고 「증가 추세입니다」라고 하는 것은 분석이 아니라 우연입니다.

## ③ 기능이 실제로 도는가

| 화면 | 확인한 것 |
|---|---|
| 수거 요청 | 서버에 실제로 `POST client_requests` 가 나가고, 응답을 받은 뒤에만 「접수되었습니다」가 뜹니다 |
| 긴급 수거 | 같은 흐름 + `urgent=true`. 내부 요청함에 붉은 「긴급」 표가 이미 붙습니다 |
| **수거 이력** | **기간·구분·찾기를 새로 넣었습니다** (아래) |
| 월간 리포트 | 달 넘기기 동작. 전월 동기 대비까지 실제 값 |
| 정산 | 청구·입금·미납이 실제 값. **결제 단추는 없습니다** — 결제 연동이 없으므로 「지금은 결제하실 수 없습니다」라고 적어 둡니다 |
| 문의 | 접수 → 확인 중 → 답변 완료. 병원은 올린 뒤 못 고칩니다(서버 RLS) |
| 알림 | 표를 만들지 않고 지금 자료로 만듭니다. 누르면 해당 화면으로 갑니다 |

### 수거 이력 — 기간을 고를 수 있게 (0086)

예전에는 **「최근 40건」 고정**이었습니다. 인증 심사에서 「2025년 전체를 주세요」라고
하면 이 화면으로는 못 냈고, 결국 전화해서 받아야 했습니다 — 이 화면을 만든 이유가
없어집니다.

- 기간: 최근 3개월 / **기록이 있는 해만** / 전체
- 구분: 실제로 나온 폐기물 유형만 (하나뿐이면 이 줄을 안 답니다)
- 찾기: 날짜·구분·용기
- 합계: **화면에 보이는 줄과 같은 건수·kg** (인증 서류에 그대로 옮겨 적는 숫자입니다)

⚠ 폰에서는 단추가 아니라 **고르는 칸**입니다. 처음엔 폰에도 단추를 늘어놓았는데,
여섯 개가 한 줄에 안 들어가 옆으로 48px 이 잘렸고 **잘린 쪽에 있던 것이 하필
「전체」**였습니다. 줄바꿈을 시키면 이 칸만 384px 이 되어 첫 수거 기록이 화면 밖으로
밀립니다(390×844 실측).
