# 0100 — 사용자 피드백 v2

> 「대표/이사와 직원들이 부담 없이 클릭만으로 사용경험을 알려줄 수 있게.
> 그리고 나중에 이 시스템이 실제 업무에 어떤 도움을 주는지 확인할 수 있는
> 사용자 기록을 쌓는다.」

## 무엇이 바뀌었나

| | v1 (0022·0076) | v2 (0100) |
|---|---|---|
| 이름 | 개발자에게 요청하기 | 사용 후기 남기기 |
| 모양 | 한 장에 체크항목 30줄 | 관점 고르기 → 묶음별 질문 → 마무리 (한 화면 스크롤) |
| 묻는 것 | 「무엇이 불편합니까」만 | 쉬워졌는가 · 줄었는가 · 계속 쓸 만한가 · 불편한 곳 |
| 관점 | 역할별 목록(현장/사무실/관리자) | **운영·관리 / 현장·실무** 두 관점 |
| 답 | 체크박스(있다/없다) | 1~5 다섯 단계 + **아직 판단하기 어려워요** |
| 사용 기간 | 안 물음 | **함께 저장** (점수를 읽는 기준) |
| 자유 의견 | 있음(선택) | 있음(선택) — 그대로 |
| 걸리는 시간 | 열면 닫고 싶어짐 | 1~2분, 전부 누르기 |

## 화면 흐름 — 한 화면에서 스크롤하며 누릅니다

```
① 어떤 관점에서 사용해 보셨나요?
   [운영·관리 관점]  [현장·실무 관점]
        ↓ 고르면 아래가 이어서 열립니다 (화면이 갈리지 않습니다)
② 어느 정도 사용해 보셨나요?   (직원은 「주로 어떤 업무를 하시나요?」 함께)
        ↓ 계속 스크롤
③ 묶음 1 / 4   필요한 상황이 잘 보이나요?      문항 5개
   묶음 2 / 4   확인하고 정리하는 일이 줄었나요?  문항 5개
   묶음 3 / 4   업무를 판단하는 데 도움이 되나요? 문항 5개
   묶음 4 / 4   계속 사용할 만한가요?            문항 5개
        ↓ 계속 스크롤
④ 마무리   체감된 변화(운영·관리) · 불편한 곳 · 하고 싶은 말(선택)

   ─ 아래에 늘 붙어 있는 띠 ───────────────
     12 / 20 답변  ▓▓▓▓▓▓░░░░
     [ 피드백 제출하기 ]
```

문항 하나: `① ② ③ ④ ⑤` + 아래에 양 끝의 뜻(← 불편함 / 매우 편함 →) +
`[아직 판단하기 어려워요]`. 고르면 그 자리에 **고른 말**이 나옵니다
(「고르신 답 — 편해요」).

### 왜 「다음 → 다음」 단계를 걷어냈나
처음에는 네 단계로 나눠 「다음」으로 넘기게 만들었습니다. 대표님이 써 보시고
바로 말씀하셨습니다 — **「그냥 계속 스크롤 내리면서 뚝 쭉쭉쭉 이렇게 할 수
있게.」** 맞는 말씀입니다. 폰에서 답하다가 다음 단추를 찾아 내려가고, 화면이
갈리고, 다시 위로 올라가는 것이 답하는 것보다 오래 걸립니다. 손가락은 이미
스크롤 중인데 흐름을 끊는 셈입니다.

그래서 **한 화면에 전부** 둡니다. 대신 묶음 제목(1/4, 2/4…)으로 어디쯤인지
보이게 하고, 아래에 붙은 띠에 「몇 문항 답했는지」와 제출 단추를 늘 띄웁니다.

- 답을 고르면 **자동으로 넘어가지 않습니다.** 스크롤은 손이 합니다.
- 같은 것을 다시 누르면 답이 **지워집니다** — 되돌릴 길.
- 안 고른 문항이 있어도 낼 수 있습니다. 억지로 채우게 하면 「아무거나」가
  들어오는데, 그건 없는 것보다 나쁩니다.
- 「사용 정도」(직원은 업무 종류까지)를 고르셔야 제출 단추가 나옵니다. 그
  전에는 무엇이 남았는지 적힌 단추가 있고, 누르면 그 자리로 데려다 줍니다.
- 관점을 바꾸면 그 관점의 문항만 세고 보냅니다. 되돌아오면 아까 고른 답이
  그대로 있습니다.

## 들어가는 문

이름은 그대로 **「사용 후기 남기기」**, 그 아래(또는 뒤)에 **「(개발자에게
요청)」**을 답니다 — 무엇을 하는 곳인지 한눈에 읽히도록.

| 자리 | 보이는 모양 |
|---|---|
| 폰 · 더보기 | 사용 후기 남기기<br>(개발자에게 요청) |
| 폰 · 도움말 시트 | 사용 후기 남기기<br>(개발자에게 요청) · 눌러서 1~2분이면 끝납니다 |
| PC · 오른쪽 위 | 사용 후기 남기기 (개발자에게 요청) — 한 줄짜리 알약이라 뒤에 |

## 「둘 다」를 고르신 분

현장 문항을 보여 드립니다. 두 벌을 다 물으면 20문항이 되어 「짧게 끝난다」는
이번 목표와 어긋납니다. 저장에는 `_work=both` 가 그대로 남으므로, 나중에
사무실 문항만 따로 여쭐 수 있습니다.

## 어디에 저장하는가 — SQL 없음

기존 요청함 표(`dev_requests`)를 그대로 씁니다. **SQL 을 새로 돌리지 않아도
오늘 바로 쓰실 수 있어야 하기 때문입니다** — 지금 이사님과 직원분이 쓰고
계십니다. `topics(text[])` 한 줄에 답 하나씩 넣습니다.

```
v2:_group=management › 운영·관리 관점
v2:_usage=d3_7 › 3~7일
v2:_work=field › 현장 수거                       (직원만)
v2:MG_STATUS_01=4 › 편해요 · 오늘 예정된 수거와 진행상황을 한눈에 확인하기 쉬웠나요?
v2:MG_EFF_01=na › 아직 판단하기 어려워요 · 현장 상황을 확인하기 위해…
v2:_benefit=전화·카톡 확인 감소
v2:_pain=속도가 느림
```

- **문항 번호**(MG_STATUS_01)를 넣는 이유: 나중에 질문 문구를 다듬어도 같은
  항목끼리 비교할 수 있어야 합니다.
- **사람이 읽을 말**을 같은 줄에 남기는 이유: 번호만 남기면 몇 달 뒤에
  아무도 못 읽습니다.
- 자유 의견은 지금까지처럼 `message` 에 그대로 들어갑니다.

### 예전(v1) 답변
그대로 있습니다. 앞에 `v2:` 가 없어 섞이지 않고, v2 형식으로 바꿔 쓰지도
않습니다. 관리자 화면에도 예전 모양 그대로 보입니다.

## 안쪽 분류 (화면에는 안 보임)

문항마다 분류를 달아 두었습니다. 나중에 「사용성은 괜찮은데 업무효율 쪽이
낮다」처럼 묶어 보기 위한 것입니다.

`USABILITY 사용성` · `EFFICIENCY 업무 효율` · `DATA 운영 가시성` ·
`DECISION 판단 도움` · `ADOPTION 지속 사용` · `SCALE 확장 가능성` ·
`CUSTOMER 고객 응대` · `ERROR_REDUCTION 실수 감소`

⚠ 답하는 분 화면에는 **절대 나오지 않습니다.** 「이건 효율 문항이구나」를
알게 되는 순간 답이 달라집니다. 검사가 이것을 매번 확인합니다.

## 숫자를 어떻게 읽는가 — 지키는 선

- 여기 나오는 평균은 **느낌 점수**입니다. 「사용성 4.2」는 「업무시간이 20%
  줄었다」와 **전혀 다른 말**입니다. 이 화면은 그 숫자를 만들어 내지 않습니다.
- 시간·비용이 실제로 줄었는지는 **시스템 기록 + 도입 전후 비교**로만 말할 수
  있습니다 (당일 입력률 · 요청 처리시간 · 재확인 횟수 — `axEvidence.ts`).
- 몇 명이 답했는지를 **늘 함께** 씁니다. 한 사람이 매긴 4.5 와 열 사람이 매긴
  4.5 는 다른데, 평균만 보이면 같아 보입니다. 그래서 「2명 / 3명」으로 씁니다.
- 「아직 판단하기 어려워요」는 평균에 **넣지 않고 따로** 셉니다. 3점으로 치면
  「보통이다」가 되는데, 그분은 보통이라고 말한 적이 없습니다.
- 심사·평가 이야기는 화면 어디에도 쓰지 않았습니다. 그 말이 보이는 순간 답이
  「잘 보이려는 답」으로 바뀝니다. 검사가 이것을 확인합니다.

## 관리자 화면 (`/dev-requests` · 「사용자 피드백」)

새 대시보드를 만들지 않았습니다. 기존 요청함 위에 요약 두 칸만 얹었습니다.

- 관점별로 나눔 — 운영·관리 / 현장·실무
- 각 칸: 답한 사람 수 · 분류별 평균(5점) · 답한 문항 수 · 판단 어려움 수 ·
  사용 정도 분포 · 가장 많이 고른 체감 변화/불편한 곳 (n명 / 전체 m명)
- 한 건씩: 관점·업무·사용 정도 뱃지 → 「n문항 답변 · 평균 x.x」 →
  고른 목록 → 자유 의견 → 「문항별 답변 보기」로 펼침
- 상태 바꾸기(접수/확인/처리 완료/보류)와 처리 메모는 그대로입니다.

## 건드리지 않은 것

수거 · 일정 · 배차 · 거래처 · 자재 · 재고 · 정산 · 청구 · 입금 · 미수 ·
대시보드 · 병원 포털 · Auth · RLS · DB. 라우트(`/dev-requests`)도 그대로입니다.

바꾼 것은 피드백 화면과 그 결과 화면, 그리고 들어가는 문의 **이름**입니다
(「개발자에게 요청하기」 → 「사용 후기 남기기」). 문이 있던 자리는 그대로입니다 —
PC 오른쪽 위 한 곳, 폰은 더보기와 도움말 안.

공용 창(Modal)에 두 가지를 더했습니다.
- `layout="sticky"` — 아래 단추를 붙여 두는 모양. **켜야만** 달라지고, 설문에서만 씁니다
- 닫기(X) 누르는 자리를 40px → 44px 로 (손가락 기준. 모든 창에 적용)

그리고 고른 상태의 글자색을 바로잡았습니다 — `t-muted` 안에 색이 들어 있어
어두운 바탕에서 부모의 흰 글자를 덮고 있었습니다(고른 「아직 판단하기
어려워요」가 회색으로 보였습니다). 이제 검사가 고른 상태의 대비까지 잽니다.
