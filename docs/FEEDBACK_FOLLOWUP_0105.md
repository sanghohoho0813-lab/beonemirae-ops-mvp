## 0. 1번은 비워 두었습니다 — 그래서 무엇이 어떻게 되는가

이사님이 말씀하신 **합성수지 6종 · 골판지 6종**과 시스템의 13개 규격(합성수지
4 · 골판지 7 · 봉투 2)이 맞지 않습니다. 어느 쪽이 맞는지는 대표님·이사님만
아십니다. 그래서 규격 목록은 **한 줄도 바꾸지 않았습니다** — 이름을 짐작해서
고치면 그 이름으로 재고와 청구가 쌓입니다.

대신 아래 작업은 **규격이 몇 개가 되든 그대로 통하게** 만들었습니다. 13개가
12개가 되어도 15개가 되어도, 「쓰는 것만 펼친다」는 규칙은 같습니다.

## 1. 거래처 정리 도우미 (0104 §3)

**어디에** — 거래처 화면 맨 위 (관리자·사무실만. 현장 담당자는 고칠 권한이
없으므로 목록만 주지 않습니다). 설정 화면의 「값이 비어서 못 쓰는 기능」
카드에도 한 줄로 붙습니다. 대시보드에는 **새 카드를 만들지 않았습니다** —
이사님이 「첫 화면이 복잡함」을 불편한 곳으로 고르셨기 때문입니다. 원래 있던
「못 쓰는 기능 N가지」 한 줄에 개수만 더해집니다.

**무엇을 모으는가** — 전부 **지금 저장돼 있는 값**으로만 판정합니다.

| 묶음 | 항목 | 판정 |
|---|---|---|
| 돈 (청구에 닿는 것) | 단가 없음 | `pricing` 에 값이 하나도 없음 → 기본 단가로 청구되는 중 |
| 매일 (매일 쓰는 것) | 주소 · 연락처 · 담당자 · 수거주기 없음 | 빈 문자열/null |
| 나중 (나중에 필요한 것) | 계약 시작일 없음 | null |
| 겹침 (이름이 비슷한 곳) | 사실상 같은 이름 / 한쪽이 다른 쪽으로 시작 | `clientNameKey` (법인격·띄어쓰기 무시) |

0104 표에 있던 **보관창고 크기**는 뺐습니다 — 이 칸은 기본값 「보통」이 있어
「비었다」를 판정할 수 없습니다. 비어 있는 척 세면 거짓 개수가 됩니다.

**순서** — 돈 → 매일 → 나중 → 겹침. 묶음마다 「왜 이 순서인가」 한 줄이
붙습니다. 묶음 안에서는 5건까지 보이고 「n건 더」로 펼칩니다.

**누르면** — 그 거래처 화면이 **수정 창이 열린 채로** 뜹니다 (`/clients/:id?edit=1`).
한 번 열리면 주소창의 `edit=1` 은 지웁니다 — 새로고침할 때마다 다시 열리지
않게. 겹침은 수정 창이 아니라 그 거래처 화면으로만 갑니다 — **무엇을 합칠지는
사람이 정합니다.** 시스템은 합치지도, 지우지도, 이름을 고치지도 않습니다.

**시연용** — 세지 않습니다. 실제 거래처와 섞여 있으면 「시연용 n곳이 섞여
있습니다」 한 줄만 알립니다.

**다 정리하면** — 「거래처 n곳 전부 정리됐습니다」 한 줄로 줄어듭니다. 카드가
사라지지 않고 한 줄로 남는 이유는 이곳이 찾아와서 보는 자리이기 때문입니다.
접기는 기억됩니다 (`localStorage`).

## 2. 수거 입력 — PC 에서도 접기 (0104 §2)

폰에서만 접던 자재 규격을 **PC 에서도** 접습니다. 규칙은 같습니다:
첫 줄 + 이 거래처에 **지난번에 준 규격** + 지금 값을 넣은 줄만 펼치고, 나머지는
「다른 규격 n개 보기」 뒤에 둡니다. 줄은 DOM 에 그대로 있습니다 — 없앤 것이
아니라 접은 것입니다. 한 번 펼치면 그 입력이 끝날 때까지 그대로입니다.

## 3. 재고 — 「쓰는 것만 보기」 (0104 §2)

자재 화면의 규격별 재고가 **최근 90일에 한 번이라도 나간 규격**과 **세어 둔
규격**만 펼치고, 나머지는 묶음마다 「n개 접힘」으로 접습니다. 묶음 위에는
**합계 한 줄**이 붙습니다 (「골판지 합계 480개 · 3개 규격 미집계」). 합계는
센 것만 더합니다 — 안 센 규격을 0 으로 치지 않고 「미집계」라고 말합니다.

나간 기록이 하나도 없으면 접지 않습니다 — 무엇을 쓰는지 알 근거가 없는데
접으면 그건 짐작입니다. 「전부 보기」는 기억됩니다.

## 4. 스스로 찾은 것 — 같은 이름으로 사용 중인 계정 (0102 의 원인)

로그인 소동(0102)의 실제 원인 하나가 **한 분이 계정을 둘** 갖고 계셨던
것이었습니다 (회사 메일 + 개인 메일). 다른 쪽으로 로그인하면 비밀번호가
「막힌 것」처럼 보입니다. 사용자 관리 화면에 **같은 이름으로 사용 중인 계정이
둘 이상이면 그 사실만** 알리는 줄을 넣었습니다 — 누구의 어느 메일인지까지.
어느 쪽을 중지할지는 시스템이 고르지 않습니다. 중지된 계정과 이름이 빈
계정은 세지 않습니다.

## 5. 같이 고친 것

- 거래처 화면에서 `?edit=1` 로 들어오면 수정 창을 열고 주소를 정리합니다 (§1).
- 설정 카드의 「값이 비어서 못 쓰는 기능」에 `clientTidy` 항목 추가 — 개수는
  정리 도우미와 같은 함수(`tidyClients`)로 셉니다. 두 자리가 다른 수를 말하지
  않습니다.
