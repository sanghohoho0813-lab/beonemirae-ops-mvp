# AX 고객사 구축 가이드

새 고객사를 계약하고 나서 **첫 로그인까지** 따라가는 문서 묶음입니다.
비원미래에서 실제로 한 번 해 본 절차를 그대로 정리했습니다.

## 읽는 순서

| # | 문서 | 언제 |
|---|---|---|
| 0 | [`00_CUSTOMER_PROFILE.md`](./00_CUSTOMER_PROFILE.md) | 계약 직후 — 고객사별로 **복사해서** 채웁니다 |
| 1 | [`01_SUPABASE_SETUP.md`](./01_SUPABASE_SETUP.md) | 프로젝트 생성 ~ 계정 발급 (STEP 1~9) |
| 2 | [`02_ROLE_MATRIX.md`](./02_ROLE_MATRIX.md) | 누구에게 어떤 역할을 줄지 정할 때 |
| 3 | [`03_LIVE_TEST_CHECKLIST.md`](./03_LIVE_TEST_CHECKLIST.md) | 계정 전달 **전** 반드시 |
| 4 | [`04_CLIENT_SPECIFIC.md`](./04_CLIENT_SPECIFIC.md) | 고객사에 맞게 고쳐야 하는 곳 목록 |
| 5 | [`05_VERCEL_HANDOFF.md`](./05_VERCEL_HANDOFF.md) | 고객사가 정식 운영을 결정했을 때 |

## 소요 시간 (비원미래 기준 실측)

| 단계 | 시간 |
|---|---|
| Supabase 프로젝트 생성 + 설정 | 10분 |
| migration 11개 적용 | 5분 |
| 계정 4개 발급 | 5분 |
| 라이브 검증 스크립트 | 3분 (자동) |
| 초기 데이터 입력 (차량·거래처) | 고객사 규모에 따라 |

## 재사용 비율

- `01` `02` `03` `05` — **모든 AX 고객사 공통.** 그대로 씁니다.
- `00` — 양식 공통, 값만 고객사별.
- `04` — 여기만 고객사마다 다릅니다. 무엇을 고쳐야 하는지 목록으로 정리해 두었습니다.

## 보안 — 예외 없음

- 이 폴더의 어떤 문서에도 **비밀번호 · API key · service_role key · 접속 문자열을 적지 않습니다.**
- 적는 것은 "값"이 아니라 **"어디에 넣는지"** 입니다.
- `.env.local` 은 커밋하지 않습니다 (`.gitignore` 에 포함되어 있습니다).
- 스크린샷도 키가 보이면 저장하지 않습니다.
- 고객사 A 의 예시 값을 고객사 B 문서에 남기지 않습니다.
