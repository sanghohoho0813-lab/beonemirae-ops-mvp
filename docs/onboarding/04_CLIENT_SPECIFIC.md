### 2-3. 업종 분류 — 업종이 다르면

DB `CHECK` 제약으로 고정되어 있어 **migration 을 하나 추가**해야 합니다.

| 항목 | 기본값 | 위치 |
|---|---|---|
| 거래처 유형 | 병원 · 요양병원 · 의원 · 장례식장 · 요양원 · 치과 · 한의원 · 한방병원 | `0001_schema.sql` `clients_type_check`, `src/types/index.ts` |
| 폐기물 구분 | 의료폐기물 · 일회용기저귀 | `clients`·`schedules`·`vehicles` 의 `waste_type` CHECK |
| 요청 유형 | 긴급수거 · 추가수거 · 소모품 · 교육·자료 · 기타 | `0006_portal.sql` `client_requests_kind_check` |
| 보관 규모 | 큼 · 보통 · 작음 | `clients_storage_size_check` |

바꿀 때는 **기존 파일을 고치지 말고** `0011_<고객사>_types.sql` 을 새로 만드세요.
비원미래 DB 에 이미 적용된 migration 을 수정하면 이력이 어긋납니다.

```sql
-- 예: 0011_acme_types.sql
alter table public.clients drop constraint clients_type_check;
alter table public.clients add constraint clients_type_check
  check (type = any (array['공장'::text, '연구소'::text, '물류센터'::text]));
```

TypeScript 쪽 `CLIENT_TYPES` / `WASTE_TYPES` 도 같이 바꿔야 화면 선택지가 맞습니다.

### 2-4. 시연 데이터 — 새로 만들거나 비우기

`src/data/seed.ts` 에 비원미래 실제 거래처 5곳 + 가상 확장 30곳이 있습니다.
**시연 모드 전용**이라 실제 운영 DB 에는 들어가지 않지만,
다른 고객사에 시연할 거면 그 고객사 거래처로 바꿔야 설득력이 있습니다.

> 실제 운영 DB 에 시연 데이터가 섞이지 않는 근거는 `05_VERCEL_HANDOFF.md` 아래
> 「시연/실사용 분리」 항목과 `03_LIVE_TEST_CHECKLIST.md` J 절에 있습니다.

### 2-5. 회사 소개 페이지 — 쓸지 말지

`CompanyHomePage.tsx` (`/company`) 는 비원미래 소개 페이지입니다 (비원미래 언급 20곳).
다른 고객사에서는 통째로 들어내거나 새로 쓰세요. 앱 기능과는 분리되어 있습니다.

### 2-6. 업종 특화 로직 — 보통 그대로 씀

| 기능 | 의료폐기물 특화도 | 판단 |
|---|---|---|
| 보관기한 임박 경고 | 높음 (법정 보관기한) | 다른 업종이면 재검토 |
| 격리의료폐기물 구분 | 높음 | |
| 전용용기·봉투·바늘통 | 높음 | 품목명만 바꾸면 구조는 동일 |
| 처리장 인계 상태 | 중간 | 폐기물 업종이면 공통 |
| 수거대장 | 중간 | 법정 서식이면 업종별 확인 |
| 배차·적재율 | 낮음 | 운반업이면 그대로 |
| 병원 포털 | 낮음 | "고객 포털"로 그대로 |
| 추천 → 제안 → 수락 → 매출 | 낮음 | 업종 무관 |
