## 2. 손으로 재는 값 (3일)

아래 네 가지는 **시스템 밖에서 일어나는 일**이라 기록이 남지 않습니다. 이것을
재려고 새 기능을 만들지 않습니다 — 3일만 손으로 적습니다.

> ⚠ 왜 3일인가: 7일 내내 적으면 적는 것 자체가 일이 되어 중간에 포기합니다.

> 견주는 것이 목적입니다. 하루 다 채우지 못한 날은 「미측정」으로 남기고
> 빈칸을 지어내지 않습니다.

### 무엇을 한 건으로 세는가

정의를 먼저 못박아 둡니다. 사람마다 다르게 세면 앞뒤 비교가 무의미해집니다.

**① 카톡 횟수** — 수거 업무 때문에 오간 카톡 **메시지 묶음**을 셉니다.
- 세는 것: 「오늘 어디 가요?」 「○○병원 몇 시?」 「그거 했어요?」 처럼 **일정·수거·자재를 묻거나 알리는** 대화
- 한 건 기준: 한 주제에 대해 오간 대화 한 덩어리 = 1건 (메시지 20개가 오가도 한 주제면 1건)
- 빼는 것: 인사·잡담·회식 이야기
- 적는 사람: 사무실(이사님)

**② Excel 재사용** — 같은 자료를 **엑셀에 다시 옮겨 적은** 횟수.
- 세는 것: 이미 어딘가 있는 숫자를 엑셀에 다시 치거나 복사해 붙인 일 (파일 1개 작업 = 1건)
- 빼는 것: 새로 생긴 자료를 처음 입력하는 것
- 적는 사람: 사무실(이사님)

**③ 전화 재확인** — **이미 있어야 할 정보**를 몰라서 건 전화.
- 세는 것: 「그 병원 몇 kg이었죠?」 「오늘 갔어요?」 「주소가 어디죠?」
- 빼는 것: 병원과의 상담·영업 통화, 새 일을 만드는 통화
- 적는 사람: 사무실·기사 각자, 하루 끝에 합산

**④ 이사님 재정리 시간** — 기사님이 준 것을 **다시 정리하는 데 쓴 시간(분)**.
- 세는 것: 손으로 적어 온 것을 옮기기, 카톡 사진 보고 표에 넣기, 빠진 것 확인하기
- 빼는 것: 청구서 만들기, 입금 확인 같은 원래 사무 업무
- 적는 사람: 이사님

## 3. 파일럿 판정 기준

숫자를 모은 다음 무엇을 보고 「됐다/안 됐다」 할지 **미리** 적어 둡니다.
끝나고 나서 정하면 나온 숫자에 맞춰 기준을 움직이게 됩니다.

| 보는 것 | 파일럿이 성공이라면 |
|---|---|
| 당일 입력률 | 기사님이 그날 갈 곳을 **그날 안에** 입력 |
| 수거 입력 소요시간 | 한 건 입력이 **길어지지 않음** (설명 없이 끝남) |
| 카톡·전화 재확인 | 도입 전 3일보다 **줄어듦** |
| 이사님 재정리 시간 | 도입 전 3일보다 **줄어듦** |
| 요청 처리시간 | 병원 요청이 **묻히지 않고** 처리됨 |

> ⚠ 실제 판매나 매출이 발생하기 전에는, 예상 실적이나 추정 절감액을 실제
> 성과처럼 적지 않습니다. **잰 것만** 적습니다.

## 5. 최종 E2E 가능 여부 — **YES** (조건 2가지)

기사 1명 · 차량 1대 · 병원 1곳 · 향후 일정으로 실증이 **가능합니다.**

코드·권한 쪽에서 막는 것은 없습니다. 폰 390px 과 PC 1440px 양쪽에서
로그인 → 향후 일정 → 본인 일정 추가 → 오늘 → 병원 선택 → 수거입력 →
저장·완료 → 사무실 반영까지 전 구간을 **누르는 길만으로** 확인했습니다
(`test/browser/check_pilot_e2e.mjs`, 46검사).

다만 **자료 준비 두 가지**가 남아 있습니다. 둘 다 화면에서 하실 수 있고,
개발이 필요한 것이 아닙니다.

| 남은 것 | 없으면 어떻게 되나 | 어디서 |
|---|---|---|
| 파일럿 병원의 **향후 일정** | 「앞으로 갈 곳」이 비어, 미리 보고 다니는 것을 확인 못 함 | 오늘 일정 → 달력에서 날짜 선택 → 일정 추가 |
| 그 병원의 **담당 기사 배정** | 일정이 기사 전원에게 보임 (업무는 되지만 「내 일정」이 안 됨) | 거래처 상세 → 담당 기사 |

> 담당 기사를 아무도 배정하지 않으면 **모든 기사에게 보입니다.** 이것은 결함이
> 아니라 정한 규칙입니다 — 한 명이라도 배정하는 순간 그 사람에게만 보입니다.
