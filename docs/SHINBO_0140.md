## 발표 클릭 순서 (0142 · 9단계 · AI 먼저)

원래 AX 화면 그대로(왼쪽 메뉴 · 위쪽 도구) — 안내 카드는 메뉴 아래쪽 위에 뜹니다. 카드의 **설명**을 읽고 **누를 곳**을 누르면 됩니다.
보라색 표는 그 단계에서 **실제로 도는 AI**, 「개발 예정」은 아직 없는 고도화입니다.

| STEP | 화면 | 실제 AI | 누를 곳 |
|---|---|---|---|
| 1 | 고객 요청 (시연 요청 하나만 보임) | **AI 요청 분석** + **AI 처리 계획** (원하는 것 · 차량 · 재고 · 이력 · 처리 순서 · 구체 회신) | 회신 남기기 → AI 분석 실행 → 분석 결과 → 처리 계획 짚기 → 이 회신 쓰기 |
| 2 | 회신 → 병원 화면 확인 | **AI 회신 초안** | 문장 확인 → 회신 저장 → 병원 화면에서 확인 |
| 3 | 대시보드 | **AI 오늘 브리핑** (숫자만 · 차량별 남은 방문 · 기다린 요청) | AI 브리핑 받기 → 할 일마다 「언제」 · 「요청함 ›」 같은 단추 |
| 4 | 수거 입력 | **AI 메모 → 수거 입력 칸 채우기** | 특이사항 펼치기 → 예시 메모 붙여넣기 → AI로 메모 정리 → 수거 입력 칸에 채우기 → 정리본으로 바꾸기 |
| 5 | 병원 포털 | (개발 예정: 병원용 AI 요청 도우미) | 긴급수거 요청 → 예시 문장 → 요청하기 |
| 6 | 미수금 (독촉 대상 칸만 · 병원 이름 가림) | **AI 안내 문구** (이름 · 금액 안 보냄) | 문구 → AI로 부드럽게 → 확인 · 복사 |
| 7 | 성과 화면 | — | 세 칸 짚기 (오른쪽 상자 — 도입 후 하루 30분 이내 · 현장 20분 → 0분) |
| 8 | AI 고도화 계획 | 지금 · 개발 예정 · 데이터 축적 후 | 세 칸 짚기 |
| 9 | 마무리 — 도입 전 → 도입 후 수치 | — | 마지막 문장 → 질문 |

- 「다음」만 누르면 1 → 9 로 이어집니다(「전체 운영 흐름 계속 보기」 단추는 뺐습니다).

### AI 가 더 깊이 관여하는 부분 (0142 · 대표님: 「누가 봐도 와! 하게」)

- **AI 처리 계획 (STEP 1)** — 「AI 분석 실행」 한 번에 요청 분석과 **같이** 불립니다(따로 기다림).
  - AI 가 요청 글에서 원하는 것(언제 · 무엇 · 몇 개 · 어느 자재 규격)을 뽑고,
  - 화면이 **그날 차량별 방문 · 사무실 재고 · 이 병원 이력(최근 수거 · 다음 방문 · 90일 긴급 · 미수)** 을 모아 AI 에 주면,
  - AI 가 그 숫자를 근거로 **처리 순서 3~5단계 · 눈여겨볼 점 · 구체 회신**을 씁니다.
  - 재고 「충분 · 부족」은 **화면이 직접 셉니다**(AI 가 말한 숫자를 믿지 않음). 회신에는 차량 이름 · 재고 숫자 · 확정 약속이 들어가면 서버가 거절합니다.
  - 병원 이름 · 기사 이름은 AI 에 보내지 않습니다(차량 이름 · 숫자만).
- **메모 → 칸 채우기 (STEP 4)** — 「오늘 85kg 수거함. 합성수지 용기 6개 … 63L 박스 5개 두고 옴 … 처리장 인계는 내일」 같은 메모에서
  수거량 · 가져온 용기 · 주고 온 자재(화면의 규격 목록에서만) · 인계 상태를 뽑아 **「수거 입력 칸에 채우기」** 를 누르면 칸이 채워집니다. 저장은 「수거 완료 저장」.
  메모에 없는 숫자 · 목록에 없는 규격이면 서버가 거절합니다.
- **오늘 브리핑 (STEP 3)** — 차량별 남은 방문 · 가장 오래 기다린 요청까지 보고 할 일 3~4가지마다 「지금 · 오전 · 오후 · 마감 전」과 「요청함 › · 오늘 일정 › …」 단추.
- **한 번 다시 묻기** — 서버 검사(지어낸 숫자 · 확정 약속 등)에 걸리면 까닭을 알려 주고 **한 번만** 다시 묻습니다. 둘째도 걸리면 실패를 그대로 보여 줍니다(고정 문구로 바꾸지 않음). 두 번 다 `ai_calls` 에 남습니다.
- ⚠ 이 기능들은 **서버 코드를 새 판으로 붙여 넣어야** 동작합니다(아래 순서 그대로 · `docs/deploy/ai-triage-dashboard.ts`). 옛 판이면 처리 계획 칸에 「서버가 이 AI 기능을 모릅니다」라고 실패로 나오고, 요청 분석은 그대로 됩니다.
- 「갈 수 있는 기사」는 AI 가 아니라 **그날 일정표에서 바로 계산**한 것입니다(차량별 방문 수 · 늘 가던 차량 ·
  그날 이미 가는 차량). 「날짜 잡기」를 누르면 그 날짜 · 추천 차량이 미리 채워지고, 확정은 담당자가 합니다.
- 위쪽 **화면 폭 좁게 · 보통 · 넓게** — 프로젝터에서 가운데로 모아 보기(글자 크기는 그대로).
- ⚠ AI 3개(브리핑 · 메모 · 문구)는 **서버 코드를 새 판으로 붙여 넣어야** 됩니다:
  Supabase › Edge Functions › ai-triage › Code → 전체 지우고 `docs/deploy/ai-triage-dashboard.ts` 붙여넣기 → Deploy updates.
  안 바꾸면 그 단추는 「서버가 이 AI 기능을 모릅니다 — 서버 코드를 새 판으로」라고 실패로 알립니다(가짜 결과 없음).

## 시연 요청 — 운영 자료와 섞이지 않게

- 시연용 거래처(시연 표 `is_demo_generated`)가 있으면 그것을, 없으면 **「시연용 병원」 하나만**
  만듭니다. 주소 · 연락처 · 사업자 정보는 비워 둡니다(지어내지 않음).
- 시연 요청: 「폐기물이 예상보다 빨리 찼습니다. 가능하면 내일 오전 수거 부탁드리고 63L 용기도 10개 부탁드립니다.」
  — 처리 완료 전의 같은 요청이 있으면 그것을 씁니다. 두 번 눌러도 하나.
- 시연용 거래처는 성과 · 실증 · IR · 준비도 숫자에서 빠지고, 그 요청의 AI 호출은 `request_triage_demo`
  로 따로 기록됩니다. 실제 거래처는 읽기만 합니다.
- 만들어진 거래처에 시연 표가 붙지 않았으면(옛 서버 등) 요청을 넣지 않고 멈추고 까닭을 보여 줍니다.
- **시연을 끄면 흔적이 안 보입니다 (0142).** 「시연용 병원」(이름이 「시연용 병원」으로 시작 · 시연 표 있음)과 그 병원의
  요청 · 일정 · 기록은 시연 중(안내 카드 켜짐)과 발표 시작 화면에서만 보이고, 대시보드 · 요청함 · 오늘 일정 · 거래처 같은
  업무 화면에서는 걸러집니다. DB 에서 지우지는 않습니다. 수거 입력 단계는 그 시연 거래처를 미리 골라 둡니다.

## 발표 전에 대표님이 할 것 (AI 연결)

### 명령어 없이 — Supabase 대시보드에서 붙여 넣기 (권장)

1. Edge Functions › Secrets › `AI_API_KEY` = Gemini 키(`AQ.…`) — 넣었으면 건너뜀
2. GitHub 에서 [`docs/deploy/ai-triage-dashboard.ts`](deploy/ai-triage-dashboard.ts) 열기 → 오른쪽 위 **Copy raw file**(복사 아이콘)
3. Supabase 대시보드 › **Edge Functions**
   - 목록에 `ai-triage` 가 **있으면**: 눌러서 **Code** → 전체 지우고 붙여 넣기 → **Deploy updates**
   - **없으면**: **Deploy a new function › Via Editor** → 이름 `ai-triage`(정확히) → 전체 지우고 붙여 넣기 → **Deploy function**
4. 앱 › 신보 발표 시연 › 발표 준비 › **지금 AI 연결 확인**
   - `Invalid JWT` 가 나오면: 함수 화면 **Details** 의 JWT 확인(Verify JWT) 끄기 → Save. 함수가 로그인 · 역할을 스스로 다시 확인합니다.

이 파일은 `python3 scripts/bundle_ai_triage.py` 로 원본에서 만듭니다(내용 그대로 · 같은 폴더 import 만 뺌 · Claude 연결 제외).
검사: `deno run --config supabase/functions/ai-triage/deno.json -A supabase/test/dashboard_bundle_smoke.ts`

### CLI 로 (개발 PC)

```bash
supabase login
supabase link --project-ref <프로젝트 ref>
supabase secrets set AI_API_KEY=<Gemini 키>   # AQ.… · AIza… 이면 Gemini 로 자동 (sk-ant-… = Claude · 그 밖 = OpenAI 호환)
# (선택) supabase secrets set AI_MODEL=<모델>    # 기본 gemini-2.5-flash-lite (이전 세대 · 가장 쌈 · 무료 등급)
supabase functions deploy ai-triage
```

- Gemini 는 Google 기본 REST(`generateContent`, 키는 `x-goog-api-key` 헤더)로 부릅니다(`gemini.ts`).
  키가 `AQ.…`(새 형식) 또는 `AIza…` 로 시작하면 다른 설정 없이 됩니다.
- 키는 CLI 대신 Supabase 대시보드 › Edge Functions › Secrets 에 이름 `AI_API_KEY` 로 넣어도 같습니다.
  **함수 배포(`functions deploy`)는 CLI 로 한 번 해야 합니다** — 새 파일(`gemini.ts`)이 서버에 올라가야 합니다.

- 키는 서버 Secret 에만. 채팅 · 저장소 · `VITE_*` · 브라우저에 넣지 않습니다.
- 앱(Vercel)이 이 브랜치의 최신 커밋을 배포하고 있는지 확인 — 아니면 병합하거나 그 배포를 운영으로 올립니다.
