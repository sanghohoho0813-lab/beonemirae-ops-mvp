# 0109 — 60초 심사 시연 투어

> 실사·심사 자리에서 대표님이 직접 돌리는 **다섯 단계**입니다 (0110 에서 여섯에서
> 줄였습니다 — 아래 11번). 기능을 늘어놓지 않고
> **한 바퀴**만 보여 줍니다 — **AX 가 시킨다 → 사람이 한다 → AX 가 확인한다.**
>
> 새 튜토리얼 엔진을 만들지 않았습니다. 이미 있는 `src/lib/tour.ts` 에 투어 하나를
> 더했을 뿐입니다.

## 0. 어디서 시작하나

`/presentation` (관리자 전용) 맨 위 → **「60초 시연 투어 시작」**

접힌 칸 안에 두지 않았습니다. 심사 자리에서 못 찾으면 없는 기능입니다.

## 1. 다섯 단계 (0110 현재)

| 단계 | 화면 | 짚는 자리 (`data-tour`) | 어떻게 넘어가나 |
|---|---|---|---|
| 1 | `/ax-coach` | `coach-total` (실증 자료 준비도) | 「다음」 |
| 2 | `/ax-coach` | `coach-go` (「수거 입력으로」 단추) | **직접 누름** → 눌러서 `/collection` 으로 가면 저절로 |
| 3 | `/collection` | `collect-save` (수거 완료 저장) | **직접 저장** → 저장 결과가 뜨면 저절로 |
| 4 | `/collection` | `collect-done` (수거 완료가 반영되었습니다) | 「다음」 |
| 5 | `/ax-coach` | `coach-done` (오늘 확인된 것) | 「AX 도입 성과 보기」로 끝 |

끝나면 `/performance` 로 이어집니다.

## 2. 읽는 단계와 **직접 누르는 단계**를 가릅니다

심사 자리에서 제일 나쁜 것은 「지금 제가 누르는 겁니까, 그냥 보는 겁니까」로
흐름이 끊기는 것입니다. 그래서 `TourStep` 에 한 줄을 더했습니다.

```ts
hands?: string   // 무엇을 누르면 되는지. 없으면 예전과 똑같이 읽는 단계입니다.
```

| | 읽는 단계 (1·4·5) | 직접 누르는 단계 (2·3) |
|---|---|---|
| 화면 | 통째로 덮여서 **안 눌립니다** (예전 그대로) | 강조한 자리만 **뚫려서 실제로 눌립니다** |
| 설명 상자 | 제목 · 할 일 · 결과 | 위에 **노란 띠**: 「직접 눌러 보세요 — …」 |
| 넘어가기 | 「다음」 | 실제로 그 일을 하면 **저절로** |

**구현 (`TourOverlay.tsx`)**

- 덮개를 위·아래·좌·우 **네 조각**으로 나누고 가운데(강조 자리)만 비웁니다.
- 바깥 상자(`fixed inset-0`)에 `pointer-events-none` 을 겁니다 — 이걸 안 하면
  구멍을 뚫어도 클릭이 바깥 상자에서 먼저 잡힙니다 (실제로 그래서 안 눌렸습니다).
  덮개 조각과 설명 상자에만 다시 클릭을 켭니다.
- **한 번 도착한 뒤에는 끌고 오지 않습니다.** 없으면 「수거 입력으로」를 누르는
  순간 투어가 다시 `/ax-coach` 로 되돌립니다 — 누르라고 해 놓고 못 가게 막는 셈입니다.
- **다음 단계가 짚을 자리가 화면에 나타나면 저절로 넘어갑니다.** 그 자리가
  생겼다는 것은 그 일이 실제로 벌어졌다는 뜻입니다 (`collect-save` 가 보이면
  수거 입력 화면으로 옮겨 간 것, `collect-done` 이 보이면 저장이 끝난 것).

세 가지 모두 **`hands` 단계에만** 걸립니다. 기존 세 투어는 한 글자도 안 바뀝니다.

## 3. 왜 이 순서가 「진짜 쓰는 시스템」으로 보이나

②에서 누르는 단추는 **실제 미션 단추**입니다. 누르면 「오늘 이 일을 받았다」는
발행 기록이 남고, ③에서 저장하는 수거 1건은 **그날의 실제 기록**입니다.
그래서 ⑤에서 AX 코치가 「실제 업무기록을 확인했어요」를 띄웁니다 —
**단추를 눌러서가 아니라 기록이 실제로 생겼기 때문에** 뜨는 것입니다.

시연용 가짜 데이터를 만들지 않기 때문에 이 순서가 성립합니다. 반대로
**시연 모드에서는 성립하지 않습니다** (아래 5번).

## 4. 새로 단 앵커는 넷뿐입니다

| 앵커 | 파일 | 원래 있던 것 |
|---|---|---|
| `today-focus` | `components/TodayFocus.tsx` | ✅ 재사용 |
| `collect-save` | `pages/CollectionInput.tsx` | ✅ 재사용 |
| `coach-total` | `pages/AxCoach.tsx` | ➕ 추가 |
| `coach-go` | `components/axCoach/MissionCardView.tsx` | ➕ 추가 |
| `collect-done` | `pages/CollectionInput.tsx` | ➕ 추가 |
| `coach-done` | `pages/AxCoach.tsx` | ➕ 추가 |

`coach-go` 는 **「오늘 수거 바로 입력」 일**에 답니다. 그 일이 없는 날(오늘 예정
방문이 없을 때)은 첫 번째 일에 답니다 — 없는 자리를 짚으면 투어가 빈 화면을
가리킵니다.

## 5. 시연 전에 반드시 확인할 것

1. **시연 모드로 하지 마세요.** 시연 세션에서 만든 기록은 `demoSessionId` 가 붙어
   실증 표본에서 **제외**됩니다 → ⑤단계의 「확인했어요」가 안 뜹니다.
2. **오늘 예정 방문이 1건 이상** 있어야 ②단계 단추가 「수거 입력으로」가 됩니다.
   없으면 `/plan` 에서 미리 편성해 두세요.
3. **실증 시작일**(설정)이 오늘보다 앞이어야 합니다. 없으면 준비도가 전부 0% 입니다.
4. ③단계에서 **거래처·차량·수거량은 직접 고르셔야 합니다.** 미션 단추는
   `/collection` 으로만 보내고 그 건을 미리 채워 주지는 않습니다.
5. ③단계에서 저장하면 **진짜로 저장됩니다.** 잘못 눌렀으면 저장 직후 화면의
   「되돌리기」로 되돌립니다 — 되돌린 사실도 감사기록에 남습니다.

## 7. 아직 안 한 것 (승인 대기)

- **폰 단계(`stepsMobile`)** — 지금은 데스크톱 단계 하나입니다. 폰에서 열면 같은
  다섯 단계가 그대로 돌아가되, 좁은 화면에 맞춘 문장·자리는 아직 없습니다.
- **③단계 사전 채움** — 미션 단추가 `/collection?schedule=<id>` 로 가면 거래처·수거량이
  미리 채워져 시연이 더 매끄럽습니다. 다만 그것은 AX 코치의 이동 대상을 바꾸는
  일이라(모든 사용자에게 영향) 손대지 않았습니다.
- **영상 제작·녹화** — 하지 않았습니다.

# 0110 — 투어를 「작은 상태 머신」으로

대표님이 직접 돌려 보고 세 가지를 지적하셨습니다. 전부 같은 뿌리였습니다 —
**투어가 화면의 상태를 읽지 않고 자기 시계로 움직이고 있었습니다.**

## 8. 딜레이가 왜 생겼나

한 단계를 그리기까지 **기다리는 곳이 세 군데**였습니다.

| 어디 | 예전 | 지금 |
|---|---|---|
| 짚을 자리 높이 재기 | 50ms × 최대 40회 두들김 | 나타나는 **그 프레임**에 (`MutationObserver` + `requestAnimationFrame`) |
| 배치 계산 전 다시 찾기 | 같은 폴링을 **한 번 더** | 같음 — 이미 있으면 기다림 0 |
| 스크롤 뒤 | 고정 `40ms` | 두 프레임 (`behavior:'auto'` 는 그 자리에서 끝납니다) |

폴링은 화면이 **이미 준비된 뒤에도** 다음 두들김 차례까지 최대 50ms 를 놉니다.
그것이 단계마다 두 번씩 쌓여 「투어가 잠깐 멈춘다」로 느껴졌습니다.
고정 시간을 없앤 대신 **번쩍임은 그대로 막습니다** — 자리를 다 잡기 전에는
강조와 설명 상자를 `opacity: 0` 으로 둡니다(예전과 같습니다).

## 9. Step 을 어떻게 기억하나

`TourContext` 가 진행 중인 단계를 `sessionStorage` 에 적습니다.

- **심사 시연(`demo`) 투어만** 기억합니다. 매일 쓰는 역할 투어(staff·field·client)는
  예전 그대로 — 새로고침하면 끝납니다. 익숙한 동작을 바꾸지 않습니다.
- **같은 탭에서만 · 2시간.** 탭을 닫거나 2시간이 지나면 이어 주지 않습니다.
- **끝내면(X·건너뛰기·마지막 단계) 즉시 지웁니다.** 다음에 열면 언제나 1단계입니다.

## 10. 뒤로가기를 누르면 어떻게 되나

화면과 단계를 맞추는 규칙을 **한 곳**에 모았습니다.

1. 이미 이 단계의 화면에 있다 → 아무것도 안 합니다.
2. 사용자가 화면을 옮겼는데 **그 화면을 맡는 단계가 있다** → 투어가 **그 단계로 따라갑니다.**
   뒤로가기·앞으로가기·직접 클릭이 전부 여기서 해결됩니다.
   (한 화면을 두 단계가 맡을 때는 — `/collection` 의 ④·⑤ — 지금 단계에서 가까운 쪽)
3. 이 단계에 아직 한 번도 도착한 적이 없다 → 그 화면으로 한 번 데려갑니다.

그 밖에는 그대로 둡니다. 예전에는 규칙이 「이 단계의 화면이 아니면 무조건 되돌린다」
하나뿐이라, 뒤로가기를 누르면 투어가 즉시 도로 끌고 갔습니다.

⚠ 「직접 누르는 단계」의 자동 넘김은 **아직 그 단계의 화면에 있을 때만** 겁니다.
화면이 이미 다음 쪽으로 넘어간 뒤에도 걸려 있으면, 위 2번이 「따라가기」를 하는
사이에 자동 넘김이 「한 칸 더」를 눌러 **한 단계를 건너뜁니다.** 앞으로가기를
눌렀을 때 한 칸 더 간 자리가 나오던 원인이 이것이었습니다.

## 11. 여섯 단계 → **다섯 단계**, 그리고 작은 상자

0109 의 설명 글은 **795자**였습니다. 소리 내어 읽으면 120초 — 60초 안에 들어갈
수가 없었습니다. **단계 수가 아니라 말이 길었습니다.**

| | 0109 | 0110 |
|---|---|---|
| 단계 | 6 | **5** (대시보드 단계를 뺐습니다) |
| 한 단계의 문장 | 제목 + 할 일 + 연결 + 결과 + 배경 (최대 5줄) | 제목 + **할 일 + 결과 (2줄)** |
| 설명 글 합계 | 795자 (낭독 ≈ 120초) | **246자 (낭독 ≈ 38초)** |
| 설명 상자 | 30rem · 화면 높이의 90% 까지 | **21rem · 화면 높이의 50% 까지** |
| 자리 | 아래를 먼저 | 자리가 있으면 **옆**을 먼저 |
| 화면의 도구 | 그대로 | 오른쪽 위 도구 줄 · 폰 하단 탭 · PC 보기 띠를 **감춤** |

대시보드 단계를 뺀 이유는 이 투어가 보여 줄 것이 **시킨다 → 한다 → 확인한다**
한 바퀴이고, 대시보드는 그 바퀴 밖이기 때문입니다. 「아침에 이 한 화면만 봅니다」는
대표님 육성이 맡습니다.

감추는 것은 **도구**뿐입니다. 저장 상태(SyncBar)와 서버 경고(SchemaBar)는 그대로
둡니다 — 시연 중에 문제를 가리는 것은 다른 이야기입니다.

기존 세 투어(대표·사무실 / 현장 / 병원)는 `compact` 표시가 없으므로 상자 크기도,
문장도, 화면의 도구도 **한 글자도 바뀌지 않습니다.** 검사로도 확인합니다
(ⓖ 「기존 투어의 설명 상자는 예전 크기 그대로 (> 400px)」).
