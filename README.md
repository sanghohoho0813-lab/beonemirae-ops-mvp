# ㈜비원미래 의료폐기물 수거·운반 운영관리 시스템 (AX)

> 경기 남양주 기반 의료폐기물·일회용기저귀 수거·운반 회사의 **실사용 중인** 내부 운영 시스템입니다.
> 현장 수거 입력 · 자재 · 청구·입금 · 병원 포털 · 권한을 한 곳에서 처리하고, AX(업무 전환) 효과를
> **지어내지 않고** 측정합니다. 이 문서는 현재 구현과 확인 상태를 사실대로 적습니다.

## 지금 상태를 한 줄로

| 구분 | 상태 |
|---|---|
| 구현 완료 (코드·로컬 검증) | 수거 입력 → 일정·이력·자재·재고·통계 자동 연결, 거래처·단가·청구·입금·통장 대사, 병원 포털(요청·물품·이력·정산), 역할별 권한(RLS), 감사로그, 오늘 업무 마감, 성과·준비 상태 화면 |
| 운영 적용 확인 | Supabase 서버(판 87 까지의 SQL 실행은 대표가 수행)에서 실계정 4~5명이 로그인해 사용. 판 106(0106 실증 기록) SQL 은 2026-09 대표가 실행해 적용됨 (5 · 106 · 4 · 5 확인) |
| 실사용 확인 | 운영이사 첫 실사용 피드백 1건(2026-09, 20문항 평균 3.9) — 자재 규격·거래처 정보 불일치로 엑셀 병행 중 |
| 성과 확인 | **아직 없음.** 실증 시작일 2026-08-29 이후 현장 수거 입력이 0건이라 초기 측정값이 없고, 도입 후 조사값은 추정(직접 입력)이라 비교에서 뺍니다. 회사 실적(2025 5.8억 · 2026 상반기 4.53억)은 AX 효과가 아니라 따로 표시합니다 |
| 계획 | 3.5톤 차량 추가 검토 · 본사 이전 검토(허가·계약·비용 미확인) · AI 요청 정리 배포(키 발급 대기) |

## 기술 스택

- Vite + React + TypeScript, Tailwind CSS, framer-motion, lucide-react, React Router
- Supabase (PostgreSQL · Auth · RLS · RPC · Edge Function 1개 준비)
- PWA (홈 화면 설치), Vercel 배포 구조
- 시연 모드(`VITE_DEMO_MODE=1`, Supabase 미설정 시)에서만 localStorage 를 씁니다. 실제 운영 데이터는 서버에 있습니다.

## 실행

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # dist/
npm run preview    # 빌드 미리보기 (검사가 이 주소를 씁니다)
```

환경변수(`.env`): `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`. 없으면 시연 모드로 뜹니다.

## AX 성과 — 무엇을 세고 무엇을 세지 않는가 (요약)

성과 화면은 세 칸입니다 — **요약**(기본: 기업 성장 현황 → AX 로 확인된 변화 최대 3장 → 다음 할 일 최대 3개) ·
**측정 근거**(계산식·원천자료·표본·제외·상세 비교) · **설정**(기준값·실증 시작일·운영 변화·업무 재현시험 기록).
숫자 옆에는 성격 넉 자만 붙습니다: **실적 · 초기 측정 · 업무 재현시험 · 예상·목표**. 자세한 것은
[`docs/AX_SUMMARY_0107.md`](./docs/AX_SUMMARY_0107.md).


- 표본 분류는 `src/lib/evidenceBase.ts` 한 곳입니다. 준비 상태·성과·브리핑 인쇄가 같은 기준을 씁니다.
  취소된 기록, 시연 기록, 실증 시작일 이전 연습 입력, 이관된 과거 실적은 세지 않습니다.
- **다른 범위끼리 견주지 않습니다.** 「수거 1건 입력 소요시간」은 측정값만 보여 주고, 「사무업무 시간」은
  도입 전과 같은 세 가지 일을 다시 조사한 값이 들어와야 개선율을 냅니다.
- 「반복 입력 1회」는 시스템 안의 구조값입니다. 엑셀·카톡 재입력은 첫 화면의 하루 한 줄 확인이 쌓여야 셉니다.
- 30건은 내부 표시 기준입니다. 입력한 날 14일 · 병원 5곳 · 기사 2명 · 입력 커버리지 80% 를 함께 넘어야
  「대표 성과값」이라 부릅니다 — 공식 기준도 통계적 대표성도 아닙니다.
- 추천 → 주문은 **노출 기록**(판 106)이 있을 때만 「채택」이고, 없으면 「규칙 일치」라고만 적습니다.
- 차량·인력·거점·계약 변화의 적용일을 기록해, 비교 구간에 겹치면 「AX 단독 효과 분리 불가 · 복합 개선」으로 표시합니다.
- 회사 사실(매출·거래처 수·특허 출원·벤처확인)은 `src/lib/companyFacts.ts` 에 출처·확인 상태와 함께 둡니다.
  사업계획서 기재값, 대표 전달값(원본 미확인), 전망, 운영자료 대조값을 같은 칸에 섞지 않습니다.

자세한 것은 [`docs/AX_EVIDENCE_0106.md`](./docs/AX_EVIDENCE_0106.md).

## 회사 사실 표기 원칙

특허는 **출원**(10-2026-0101187)이며 등록이 아닙니다. 벤처기업확인(혁신성장유형 2026-08-05)·연구개발전담부서는
기존 대화·자료에 근거하며 원본 서류는 이 저장소에서 확인하지 못했습니다. 매출 2023 1.19억 → 2024 3.62억 →
2025 5.8억은 기존 사업계획서 기재값, 2026 상반기 4.53억은 대표 전달값(1기 부가세 신고 기준, 원본 미확인),
2026 연말 9억 초과는 전망입니다. 거래처 약 53곳은 대표 전달값이며 시스템 등록 수와 별도입니다.

> 회사명 표기는 **㈜비원미래** 또는 **beonemirae** 만 사용합니다.
